# art —— 美术资产（生成的，不是画的）

> ⚠ **先读 [资产定义](asset-list.md)（`docs/asset-list.md`）** —— 那是"这个游戏有哪些资产"的规格。
> 本文只管"怎么生成"。生成器是实现的一种，随时可以改/换；规格先定。


> **画风 = 6 条规则 + 一张色板。规则写在 `style.json`，代码照着规则画。**
> 改画风 → 改 `style.json`；加人 → 加 `characters.json` 一行。不用重画任何东西。

```bash
bash art/build.sh          # 一条命令：生成 → 校验 → 出联络表
# 验收在 wiki 里看：bash art/build.sh 会顺带重建 wiki
open wiki/out/art.html     # 美术资产 · 按九大类 · 虚线框=缺口
```

产物 `art/out/` 是**构建产物**（已 gitignore）—— 真源是下面三个文件。

## 一、这个方法擅长什么、不擅长什么

| | |
|---|---|
| ✅ **擅长** | 平铺贴图 · 模块化建筑 · 图标 · 规则化的小人 · 阴影与标记 · **改一次色板全局生效** |
| ❌ **不擅长** | 手绘质感 · 有性格的脸 · 氛围（光照/天气的美术感）· 需要"画味"的东西 |

所以这套东西的定位是：**把占位美术做到"能看"，并且做到"可整体替换"**。
它不取代美术 —— 它让美术来之前游戏就能跑，并且**给出确定的规格**（网格/锚点/命名/图层），
美术接手时不用猜。

**当它不够用时**（要质感、要表情、要氛围），按同一份清单交图替换即可：文件名、尺寸、
锚点、图层都已经定死（见 §五）。生成器只是"最省事的那一版实现"。

---

## 二、画风 = 这 6 条规则

写在 `style.json` 的 `rules` 里。**这是整套东西唯一的"审美判断"**：

```
① 平涂 + 1px 深色描边。不用渐变做体积（渐变只用在"高光偏一点"和"水"）。
② 俯视，但底部留 4~5px 的立面揭示 = 假的厚度。这是"看着立体"的全部秘密。
③ 落影单独一层（偏移 4,5 · 黑 10%），方便夜/雨复用、也方便关掉。
④ 一切对齐 32 网格。不许有半格的东西。
⑤ 单个资产最多 5 个颜色。多了就说明该拆图层。
⑥ 纹理 = 1px 重复图案，透明度 ≤22%。不用噪点、不用颗粒（缩小会糊成脏块）。
```

规则 ② 是原型的"城市感"最大的来源 —— 建筑底下那 5px 的墙，就是一个平涂矩形看起来
像房子的原因。

## 四、怎么改

### 换画风
改 `style.json` 的 `palette`，重跑 → **174 个资产一起变**。
（比如把草地从 `#6d8a52` 改成秋色，整张地图立刻变季。）

### 加一个人
`characters.json` 里加一行：

```json
{ "id":"n_chen", "name":"陈师傅", "body":"stocky", "skin":1,
  "hair":"white", "top":"#6b7a5a", "acc":"bag" }
```

重跑 → 自动生成他 3 向 × 5 帧 = 15 个文件 + 清单条目。
**不用碰 gen.mjs，也不用碰前端。**

新增后会自检：

```
$ node art/gen.mjs --check
角色可辨识性：9 人，两两 36 对
  ✓ 任意两人至少 3 维不同（身体/头发/上衣/配饰/肤色）
```

不满足会报出**是哪两个人在哪几个维度撞了**，比如：

```
✗ me(陈知远) vs n_lin(林静)：只差 2 维 [top,acc]
```

> 这条是契约的硬要求（`contracts.md`：可区分性 > 随机性）。
> 因为 Demo 的验收第①条就是「**我认得他们**」—— 玩家要一眼认出"那是王阿姨"。

### 加一个物品
`gen.mjs` 的 `ITEMS` 数组加一行（`{id, name, w, h, empty, world, icon, tags}`），
自动出三张：**世界形态（俯视）· 空态 · 图标（正视）**。

清单照 `config/items/*.json` 来 —— **物品是配置定义的，不是这里编的**。
现在有 9 件：

```
货·消耗品   苹果 · 梨 · 简餐        ← 会卖光，所以额外给一张【空态】
原料        简餐原料
家具        床 · 前台 · 工位 · 工业机器 · 马桶
```

★ **物品需要两套"语言"，这是故意的**：

```
世界形态 = 俯视   地图是俯视的，货摆在地上要贴地
图标形态 = 正视   16px 的小图标，正视才认得出来 —— 俯视的苹果就是个圆
```

★ **空态 = "卖光了"的世界表达**（P6：能用形状就不用文字）。
只有会消耗的货才有空态，家具永远满。

### 加一栋楼
`gen.mjs` 里的 `BUILDINGS` 数组加一行（`{id, kind, g:[宽格,高格], v:变体}`），
自动生成三张：本体 / 落影 / 夜间窗光，外加门与招牌位的坐标写进 `manifest.json`。

## 五、产物契约（前端只认这个）

`out/manifest.json`：

```json
{ "grid": 32, "authorScale": 2, "logicalSize": true,
  "buildings": [ { "id":"shop_a",
                   "doors":[{"side":"south","offset":0.46}],
                   "sign":{"x":7,"y":6,"w":242,"h":13} } ],
  "assets": [ { "name":"n_wang_down_walk0", "file":"people/n_wang_down_walk0.svg",
                "w":18, "h":24, "anchor":"bottomcenter", "layer":"L4",
                "tags":["person","n_wang","down","walk","f0"] } ] }
```

| 字段 | 含义 |
|---|---|
| `w` / `h` | **逻辑尺寸**（不是文件里的像素尺寸） |
| `anchor` | `topleft` 地图件 · `bottomcenter` 立在地上的东西 · `center` 标记 |
| `layer` | L0 地面 · L1 路 · L2 装饰 · L3 建筑 · L4 实体 · L5 夜间 · L6 标注 |
| `authorScale: 2` | SVG 按 **2× 绘制、按 2× 声明**。Pixi 里 `sprite.scale = 1/2` |

**为什么 2×**：超过 2× 缩放时纹理才不会糊（相机上限 2.4×）。
SVG 是矢量的，浏览器里任意缩放都锐；但 Pixi 会把它栅格化成纹理，所以声明尺寸要给足。

**招牌上的字不进贴图** —— 招牌底留白，字由代码画。
因为编辑器能改建筑名，写进贴图就死了。

**锚点别改**：`bottomcenter` 的东西（树/人/车/长椅）你把锚点从脚底挪到中心，它们就全都
浮在半空。这是最容易犯又最难查的错。

## 六、为什么有 `verify.py`

生成的 174 个文件不能靠肉眼验收。它检查五件事：

```
① 清单里每个文件都在，且是合法 XML
② 声明尺寸 == 逻辑尺寸 × authorScale   ← 错了 Pixi 里就糊或者错位
③ 没有 NaN / undefined / null 混进坐标
④ 所有 url(#id) 都指得到对应 <pattern>  ← 引用不到 = 那块直接不画（静默失败）
⑤ 所有 fill / stroke 都是合法颜色
```

它抓过真问题：落影画布故意比建筑大一圈（偏移余量），但清单里我写成了建筑尺寸 →
`②` 当场报出来。这类错在浏览器里只表现为"影子偏了一点"，肉眼几乎发现不了。
