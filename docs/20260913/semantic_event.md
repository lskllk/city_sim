# SemanticEvent —— NPC 语义层设计

> 状态：设计稿（未实现）。本文冻结"NPC 如何把内部状态说成人话"这一层的结构，
> 实现分期见第 9 节。
>
> 一句话：**NPC 说出口的话，是从真实内部状态长出来的 `SemanticEvent`；它经渲染层措辞、
> 经校验层保真，并且它本身同时是一次信息传播事件。**

---

## 1. 不可违背的原则

1. **随机只在措辞层。** 语义层（谁 / 知道什么 / 什么行为 / 什么强度）必须是真的、确定的。
2. **准确性靠约束，不靠更聪明的模型。** 用校验器卡死，而不是指望模型自觉。
3. **语义系统 = 知识系统的可视化 + 传播载体。** 不另做"台词系统"；说出的话就是一条
   带来源的 `Fact`，进入听者的记忆。
4. **知识边界优先于表达力。** NPC 只能说它**知道**的事（`believe` 过阈值的记忆 /
   自身状态 / 自身身份）。说得再漂亮，越界即错。
5. **确定性可回放。** 同 seed 同状态 → 同台词（LLM 层走缓存，见第 6 节）。

---

## 2. 数据模型

```text
SemanticEvent:
  event_id     语义事件 id
  tick         发生时刻
  speaker      npc_id
  act          言语行为（见下）
  topic        话题键（用于冷却 / 去重）  规则 ^[a-z][a-z0-9_.]*$
  slots        该 act 的内容槽（只允许真值，禁止渲染时新增实体）
  source       "" 表示来自自身；否则是 fact_id / 来源 npc_id
  intensity    0..1 → 渲染时映射为强度档
  listeners    听到的 npc_id（第 11 节待定其判定方式）
```

`act` 枚举与**必要槽位**（槽位即"模拟必须提供的数据"，缺了就发不出这个事件）：

| act | 含义 | 必要槽位 | 例 |
|---|---|---|---|
| `STATE` | 自身状态变化 | signal, value, urgency | "我吃饱了" / "憋不住啦" |
| `INTENT` | 意图 + 理由 | goal, reason | "今天来买点菜，家里没了" |
| `SURPRISE` | 预期与观察落差 | expected, observed | "苹果卖光了？" |
| `PREFERENCE` | 偏好 | target, valence | "我爱吃苹果" |
| `REQUEST` | 请求 / 期望 | target, want | "希望能尽快补货" |
| `DOUBT` | 信念被现实推翻 | belief, observed, source | "王哥又骗我说降价了？" |
| `REPORT` | 转述 | fact_ref | "听说你这降价了" |
| `COMPARE` | 比较 / 迁移 | a, b, dim | "隔壁更便宜" |

**这张表就是本层的天花板**：模拟里没有"带来源的信念 + 信任"，就永远说不出 `DOUBT`。
所以语义层不是装饰，它是**模拟深度的显示器**——模拟越真，台词越不重复，
因为它压根不是从池子里抽的。

## 3. 主干 C：上下文决定论

```text
line = f(act, speaker, listener, source, intensity_bucket,
         relationship, mood, persona, said_recently)
```

- **不做"从池子里随机抽一句"。** 台词的取值空间是**个体历史的函数**：访客越多、历史越长，
  话越个人。
- **说话人台词记忆** `said_recently: topic → last_tick`：冷却窗口内要么换说法，要么不说。
  NPC 不会短时间重复自己。
- 设计意图：**随机常常是用来掩盖状态空间太贫乏。** 把状态空间做厚（C），随机就只需要
  最后撒一点盐。

---

## 4. 渲染层 A：组合式模板池

不写整句，拆成三段独立抽取：

```text
句子 = opener + core + tail
opener 池: 4 种    core 池: 3 种    tail 池: 4 种
→ 单 act 48 种组合，只写 11 个片段
```

- 槽位填充值也走**同义池**（"便宜 / 划算 / 不贵"）。
- 优点：便宜、确定、零延迟、可回放。
- 短板：上限由手写量决定 → 用第 5、6 节补。
- 扩展路径同方案 E：片段库可挪进数据文件，不吃代码。

---

## 5. 渲染层 B：人格 / 情绪语气层

同一事件，多套**语域（register）**，抽取时是 `语域 × 模板`，而不是一个池子：

| 语域 | `STATE.bladder` 说法 |
|---|---|
| 急躁 | "憋死了！" |
| 冷淡 | "……我去趟洗手间。" |
| 热情 | "哎哟不行了，先失陪一下哈" |
| 爱抱怨 | "这厕所怎么老排队啊" |

- 语域由 `persona`（长期）× `mood`（短期）合成。
- **不增语义、只增味道**；是"去机器人味"性价比最高的一块。
- 语域不得与强度档冲突（见第 6 节闸 3）。

---

## 6. 润色层 D：LLM paraphrase（可选，挂在上面）

```text
SemanticEvent → 结构 → LLM 只改写措辞 → 校验器 → 通过 / 降级回 A
```

**四道校验闸（准确性在这里，不在模型里）：**

1. **知识边界**——只准用 NPC 已知的事实（`believe` 过阈值）。越界即拒。
2. **不引入事件外的实体**——句子里的每个 item/location/person 必须来自 `slots`。
3. **强度档匹配**——轻微不满不得喊"气死了"。
4. **人格一致**——语域与 `persona` 不矛盾。

- 缓存 key：`(act, register, slots_fingerprint)` → 回放不重调 API（确定性）。
- 无 client / 抛错 / 校验不过 → **规则模板降级**，保证不停摆。
- 与 `npc/planner.py` 的「缓存 / 校验 / 模板降级」是**同一套路子**，直接复用该模式。

---

## 7. 传播闭环（本层的真正价值）

```text
speaker 内部状态 → SemanticEvent → 渲染成一句话
                                        │
                            listeners 听见
                                        ▼
                    写入 memory：Fact(source=speaker)
                    believe = f(trust(speaker), 内容, 新鲜度)
                                        │
                            speaker 后续被观察/被推翻
                                        ▼
                              产生 DOUBT / REPORT
```

- **气泡 = 这次 transfer 的可视化。** 所以气泡不是 UI 特效，是模拟的出口。
- T0/T1（离屏）NPC **不渲染气泡，但仍然传播**——信息照样在社会里走。
- 由此，营销 / 口碑 / 谣言天然咬合经营玩法：**它们改的是别人脑子里知道什么。**

---

## 8. 触发与过滤（不然满屏废话）

发一条 `SemanticEvent` 需同时满足：

- **跨阈值**：`饱→饿` 发；`0.70→0.65` 不发。
- **对听者算"新消息"**：听者已知且未变 → 不发。
- **有人在场**（或允许自言自语）。
- **topic 冷却**：受 `said_recently` 约束。

优先级（高 → 低）：

```text
被推翻的信念(DOUBT) > 预期落差(SURPRISE) > 意图(INTENT) > 状态(STATE) > 偏好(PREFERENCE)
```

> 信念与现实冲突的那一刻永远最好看，系统里天然排最前。

## 9. 分期实现

**M-S1（最小集，先做这个）**
- `act` 只实现：`STATE / INTENT / SURPRISE / DOUBT`
- 手写组合式模板池（A）+ 上下文决定论（C）+ 传播闭环（第 7 节）
- **不接 LLM**，不带语域（B）
- 验收：一家店 + 两三个有记忆的 NPC，能出现"靠别人告知而来"和"来了发现与听说不符"
  两种行为，且台词不重复。

**M-S2**：加语域层 B（persona × mood）。

**M-S3**：接润色层 D（缓存 + 四道闸 + 降级）。

## 附：命名约定（对齐 `docs/naming.md`）

- `act` 名：ASCII 大写下划线枚举（`STATE` / `DOUBT` …）。
- `topic`：小写 `^[a-z][a-z0-9_.]*$`，如 `item.food_apple.stock`、`shop.price.change`。
- `event_id`：`sem<N>`（与 `ev<N>` 区分，语义事件 ≠ 世界事件）。
