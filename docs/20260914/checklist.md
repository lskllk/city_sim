## 1 已实现（能跑、能看、有测试）

| 块 | 到什么程度 |
|---|---|
| **决策** | 效用主导单轨；候选不过滤，阈值只在得分上；迟滞抢占；计划只偏置（hp<0.5 时零拉力） |
| **需求** | hunger 半天 / energy（2 天基准 + 夜间陡增 + 睡觉回满）/ bladder 1.6 天 + 三餐跳量 |
| **生命** | hp 三态（只 hunger/energy 参与；中间带不动）；归零 → 死（`npc_died`） |
| **买卖** | 扣钱 → 减店库存 → 送货进家容器（合并、保质期取最早）→ 变质销毁。**卖家不收钱** |
| **囤货** | 目标存量由保质期推导；只对 `consumable` 生效；缺口只驱动补货 |
| **感知 → 记忆** | `EntityView → MemItem`；`believe/remember/source`；写入口只有感知与传闻 |
| **传播** | 一对一搭桥（说/听各掷骰子；说的不听/听的不说；同屋高、路人低）；六条硬规则；信任两档 |
| **语义层 + 气泡** | 6 种 act + 模板池（确定性措辞）；气泡只在关注范围冒，两侧都写"谁给谁说" |
| **空间** | 多楼层（`_f1..fN` + `part_of`，容量×层数）；家 = 楼层单元；旅行按路径折线插值 |
| **观察驱动推送** | 60Hz；只推变化的 ∪ 观察集；超时丢帧不断线；HUD 流量 |
| **编辑器** | 路网/建筑/楼层/住户/物件/认知(批量)/按人记忆/无住所的人面板/导入导出；建筑名自动编号 |
| **观察器** | 只读镜像 + LOD 分级标签 + Event Log + Inspector（记忆/事件/意图/决策理由） |
| **确定性** | 同 seed 可回放；随机只走 `systems.rng`（不用内置 `hash()`） |

## 3 待拍板

| # | 问题 | 影响 |
|---|---|---|
| 1 | **经济走规模线还是品质线**（更大的店 = 更赚钱，还是能卖更贵？） | 决定后面所有经济设计 |
| 2 | 店员是什么：**会累的加速器** 还是 **会跟顾客建关系的人** | 后者咬合支柱 A，成本高 |
| 3 | **一天多长 / 快进尺度**（现在 1 天 = 1440 tick = 24 分钟 @1x） | 决定气泡产生密度 |
| 4 | **气泡信息量上限**：满店顾客怎么不糊（分级？距离？重要度？） | 直接决定好不好看 |
| 5 | **面板打开时世界走不走**（倾向：走） | 经营手感 |
| 6 | **招牌**：建筑字段还是实体？`source="sign:<bid>"`，检测半径 R | ④ 的实现形态 |
| 7 | **多层建筑的目的**：真实感 / 玩法 / 容量 | 影响后面要不要做"上楼" |
| 8 | `mind.md`（情绪/关系/信任）**什么时候做** | 它是 P6"骗"玩法的前置 |
| 9 | 老需求里的 **Company/School/日结月结/技能** 要不要按原样做 | ① ② 的范围 |
| 10 | 归档的那批文档：**删除**还是留档 | 仓库整洁度 |
