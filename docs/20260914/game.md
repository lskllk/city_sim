# CitySim 游戏定位 —— 开店老板 × 活着的城市

> 状态：**指导性文档（游戏方向总纲）**。上位：`docs/Vision.md`。
> 本文件**约束** `docs/20260913/*` 四条机制文档的定位与优先级；机制细节仍以那四篇为准，
> 但"做哪条、为什么做、做到什么算好"以本文件为准。
>
> 一句话：**玩家扮演一名开店老板，在一座由真实 NPC 组成的城市里经营；顾客头顶的语义气泡，
> 把"城市是活的"这件事直接摆在玩家眼前。**

---

## 1. 这是什么游戏

**商业城市生活模拟（shop-owner life sim），玩家操作一个 NPC。**

玩家不是上帝视角的经理，也不是看数据面板的运营。玩家是**城里的一个人**——一个店主。
他通过经营店铺赚钱，用钱换更好的资源与体验，并把生意做大。

```text
玩家（老板，是一个 NPC）
   ├─ 布置店铺     货架 / 货物 / 陈设 / 价格
   ├─ 招募店员     雇 NPC 帮他干活（拿工资、会累、会偷懒、会跟顾客熟络）
   ├─ 进货 / 定价  决定卖什么、卖多少钱
   └─ 扩张         更大的店 / 更多的店 / 更好的位置

城市（其余全是 NPC）
   └─ 顾客是真实 NPC：有身体、有日程、有记忆、有关系、有信任
```

**反面清单（明确不是这些）**：

| 不是 | 因为 |
|---|---|
| 上帝视角经营面板 | 玩家是一个 NPC，受同一套身体/资源约束 |
| 客流量 + 满意度 的数字游戏 | 见 §3 支柱 A —— 顾客是对象，不是统计 |
| 纯 UI 气泡的"氛围装饰" | 见 §3 支柱 B —— 气泡是**玩法界面** |
| 观察器 / 实验台 | 那是 `Vision.md §23` 的 Observatory，是本作的**开发工具**，不是玩家玩法 |

### 1.1 具身化管理：管理物件（电脑）与经营面板

**老板是一个可自由行动的 NPC**（不是上帝视角，受同一套身体/时间/交互约束）。
但他需要全局信息与批量操作（招聘 / 定价 / 管理），这靠**特殊物件**提供：

```text
与「电脑」交互  →  弹出经营面板（招聘 / 定价 / 库存 / 账目…）
```

**这是本作解决「具身 vs 管理」这个矛盾的答案：**

- 面板不是「上帝能力」，是**一件家具的功能**——要管理，先走到电脑前。
- 电脑会被占用 / 坏掉 / 没电（`claimed` / `cool_until` 现成）→ **管理能力本身是稀缺资源**。
- 升级电脑 = 升级管理能力 → 与「赚钱换更好的资源与体验」天然闭环。
- 用电脑是**一条可被他人感知的交互** → 将来可做「谁在用电脑 / 谁看见你干了什么」。
- 扩展方向：管理物件不止电脑（账本 / 招牌 / 电话 / 货架本身）。

**待拍板的基础问题：面板打开时，世界时间走不走？**

| 方案 | 体验 | 代价 |
|---|---|---|
| A 暂停 | 可以从容完美应对 | **「即时运营」被打断**，玩家在暂停里消除一切压力 |
| B 继续（推荐） | 老板在电脑前 = 在忙；顾客照样进店、气泡照样冒 | 手忙脚乱——但这是《双点医院》/《环世界》的核心张力 |

本文档倾向 **B**：面板只是渲染层，老板实际处于「使用电脑」这条交互中，
**管理是要花时间、有代价的**——支柱 A 对玩家自己也成立。

### 1.2 【已定死】面板上的操作只改「世界真值」，不碰 NPC 的知识

> **玩家的手只能碰世界，碰不到 NPC 的脑子。**

- 玩家点「苹果 10 → 8」→ `world` 里的价格**立刻**变成 8，
  **但没有任何 NPC 知道** —— 哪怕他从没去过店里。
- NPC 只能通过**感知**（进店看见）或**传闻**（别人告诉）获得这个事实。
- 于是：**改价本身有传播延迟**，促销变成一场赌博（何时降 / 降多少 / 多久传开 / 传多远）。
- 玩家会困惑「我降价了怎么没人来」→ 所以**观察 UI（气泡 / Inspector）是必需品**，
  以及**主动投放渠道**（招牌，见话题 3）。

**为什么必须定死**：一旦允许「全局同步 NPC 知识」（= 玩家直接写 NPC 的脑子）：

- 支柱 A **当场死** —— 顾客不需要“看见”就知道，感知/记忆/传播全部失去意义；
- 游戏退回《便利商店》：调一个数，数值就变了；
- 气泡也没内容可说 —— “听说降价了”这个说法根本不成立。

> `mind` + `semantic_event` + `memory` 之所以是这个游戏唯一的引擎，
> **完全建立在“知识有边界”之上**。见 §6 红线 3。

## 2. 核心循环

```text
            ┌──────────────────────────────────────────────────┐
            │                                                  │
  进货 ──→ 开门营业 ──→ 顾客进店 ──→ 服务 / 成交 ──→ 赚钱 ──→ 更好的
            ▲            (真实需求)      │                    资源与体验
            │                          ▼                        │
            │                   💬 气泡反馈                      │
            │            (情绪 / 记忆 / 传播)                    ▼
            │                          │                     扩张 / 开店
            │                          ▼                        │
            └────────── 口碑改变进店人群 ←──────────────────────┘
                     （影响整座城市）
```

关键：**右下角那条回流线**。玩家赚的钱和好体验，最终必须能反哺到"谁进我的店、
他们信什么、他们怎么跟别人说起我"。这就是 `docs/20260913/semantic_event.md §7`
说的「营销改的是别人脑子里知道什么」——在本作里它是**真实机制**，不是文案。

## 3. 两条不能丢的支柱（本作的全部差异点）

### 支柱 A：顾客是真实 NPC，不是数据

- 顾客**因为真实需求才来**：他有 `hunger` / `fun` 等信号，有日程（`plan.md`），
  有自己的记忆（`memory.md`）和关系/信任（`mind.md`）。
- 他不知道为什么来"你这店"，他知道的是"**我听王哥说**你这便宜"（带 `source` 的记忆）。
- **禁止**引入"客流量""平均满意度"这类抽象层。那正是别的经营游戏的做法，
  也正是本作要否掉的东西。要看宏观，从个体**数**出来（`Vision.md §23`）。

> 这条决定了玩家能玩到的深度：玩家的每一个经营动作，最终都作用在
> **具体某个 NPC 的某个具体信念**上。

### 支柱 B：气泡 = 语义层可视化，玩家唯一的"读心窗口"

顾客进店后，**头顶冒出气泡**：情绪、记忆、信息传播，用可视化的形式直接呈现。

- 气泡是**语义层（`semantic_event.md`）的出口**，不是 UI 特效。
- 它是本作的 **HUD、juice、反馈回路三合一**：玩家靠它知道"顾客此刻在想什么 / 刚听说了什么"。
- **所以气泡必须是真的。** 它由 NPC 的真实内部状态长出（`semantic_event.md §1.1`：
  随机只在措辞层）。玩家会**相信并依据**气泡做经营决策——
  "顾客说太贵了" → 玩家降价；"听说隔壁更便宜" → 玩家去查隔壁。
- **气泡撒谎 = 游戏撒谎。** 这是不可违背的红线（见 §6）。

```text
顾客内部真实状态
   → SemanticEvent（谁 / 知道什么 / 什么强度，全部为真）
      → 气泡（渲染层措辞 + 语域）
         → 玩家读出 → 玩家行动 → 顾客反应 → 新的气泡
```

这一个环，就是本作的"游戏性核心"：**玩家在和一个活人做生意，而不是和一个计数器。**

## 4. 这重排了 20260913 那四篇的定位

| 文档 | 原本定位 | **在本作里的新定位** |
|---|---|---|
| `semantic_event.md` | NPC 语义层（设计稿） | **核心玩法界面**——气泡是玩家读心和口碑传播的窗口 |
| `mind.md` | 情绪 / 关系 MVP | **气泡的内容来源**（情绪→气泡）+ **口碑引擎**（信任→believe→传播） |
| `plan.md` | 计划表 / 日程模板 | **背景层**——让"顾客为什么这个点出现"有解释、让世界可预测 |
| `memory.md` | L0 + L1 记忆 | **地基**——气泡不重复、可追溯、`source` 可信 的前提 |

**排序结论（游戏视角，非依赖视角）：**

```text
mind（+MemItem.source）   ← 先有"信 / 不信"，气泡才有内容，口碑才成立
   ↓
semantic_event M-S1       ← 把内心变成玩家看得见的气泡（本作的玩法界面）
   ↓
plan（F1+F2）             ← 让顾客到店有理由、有节奏、有偏离
   ↓
memory（Episode）         ← 让气泡不重复、让玩家能追问"为什么"
```

变化点：**`semantic_event` 从"最后做"提到"最前面"。** 因为在观察器游戏里它是装饰，
在店主游戏里它是**主界面**。没有它，玩家什么都看不见，支柱 B 直接塌。

> 上一轮（工程视角）我把 plan 排第一，理由是依赖。
> 这一轮（设计视角）我把 mind + semantic 排前面，理由是：**先让玩家看得见 NPC 的内心。**
> plan 依然重要，但它是舞台布景，不是演员。

**落地时进一步压缩（见 `docs/20260914/mvp.md`）：** mind 与 semantic 在 MVP 里被裁成同一根线，
只做「一行带 `source` 的记忆 → 同地折扣传递 → 头顶气泡」。trust / verify / 情绪 / 计划 全部推迟为
往后挂的插件。

## 5. 玩法上"必须发生"的几件事（验收的另一种写法）

不是单元测试，是**应该被玩家看到的桥段**：

1. **降价 → 传开 → 带来新客。** 玩家把苹果降价，一个顾客看见并告诉邻居；
   第二天来的人里，有人是"听说的"。
2. **贵 → 被抱怨 → 改 → 回头。** 顾客气泡冒"太贵了"，玩家改价，同一顾客下次满意。
3. **店员是人。** 雇来的 NPC 店员有工资、会累、会跟常客变熟；
   "熟客"这件事影响成交与麻烦（未来）。
4. **一件事改变一个人的信念。** 玩家一次缺货 → 某顾客记忆更新 → 他不再特地来。
5. **玩家能看见因果。** 点一个顾客 → 能看到"他为什么来 / 他听谁说的 / 他现在信几分"。

**反验收**：如果玩下来，玩家发现"我改价格只会让一个满意度数字动一下"——
说明 NPC 已经退化成统计，支柱 A 已死。

## 6. 设计红线（新增，优先于机制文档的细节）

1. **知识边界（定死，最高优先级）。** **玩家的手只能碰世界，碰不到 NPC 的脑子。**
   经营动作**只写世界真值**；NPC 的知识**只能**由**感知**（`perceive_into`）或
   **传闻**（`_notify_due`）写入。**禁止任何"全局同步 NPC 知识"的捷径**（§1.2）。
   两侧都锁死：**读** —— `decide` 只读记忆不读世界（已有）；
   **写** —— 记忆只能由感知/传闻写（新）。→ `World Truth ≠ NPC Knowledge` **架构上不可违反**。
2. **气泡必须真、且可行动。** 由真实状态长出；玩家能据此做出更好的经营决策。
3. **顾客不得退化成统计。** 禁止抽象出"客流量 / 平均满意度"一类聚合层当玩法输入。
4. **一切经营动作最终落在具体 NPC 的信念上** —— 但**只能经由感知 / 传闻**到达，不能直写。
5. **实时运营 ≠ 破坏确定性。** 气泡走纯读快照（`gateway/snapshot.py`）；
   前台渲染、后台传播可分离：**视野外 NPC 不冒泡，但仍继续传播**
   （`semantic_event.md §7`）。
6. **看不见 ≠ 没发生。** 玩家只经营一家店，但城市在视野外继续演化——
   这正是"玩家影响整座城市"的来源。
7. **原有铁律不变**：`npc/` 不 import `world`；计划只偏置不门禁；随机只在措辞层。

## 7. 与既有架构的关系

三层决策（`20260910/requirements.md §1`）仍然成立，但换到玩家视角：

```text
第1层 身份 / 角色     NPC 是打工人 / 学生 / 主妇 / 店员……
第2层 计划（偏置）    今天 12:00 午休想去买点吃的 ← 玩家要抓住的就是这些"窗口"
第3层 本地策略       进店后看货架 → 买不买 → 买什么（气泡在此冒出）
                     ↓
           玩家（老板）在这一层与之相遇：货、价、人
```

**玩家的操作面，正好落在"第 3 层 + 世界侧"**：布置货架、定价、雇人。
玩家买不到、也改不了 NPC 的日程；玩家只能通过**改货、改价、改体验、改口碑**
去影响 NPC 的**选择**。这就是这个游戏的"深度在数据，操作在环境"。

## 8. 设计决策与待拍板

### 已定

- **P1 【已定】老板是一个可自由行动的 NPC。** 不是上帝视角，受同一套身体 / 时间 / 交互约束。
  全局管理能力由**特殊物件**提供（见 §1.1）：与电脑交互 → 经营面板（招聘 / 定价 / 管理）。
- **P6 【已澄清】"骗"的两个方向，共用同一套 `verify`/`trust`：**
  - **玩家 → NPC：** 虚假宣传（"最后一天大甩卖"）、以次充好、雇托刷好评。
    若允许，`mind.verify` 是**唯一惩罚**——顾客到店发现不符 → 信任下降 → 口碑崩。
    这是玩家**故意在气泡层制造一个假信念**，赌它什么时候被戳穿。
  - **NPC → 玩家：** 店员虚报库存 / 偷钱、供应商以次充好、对手放谣言。
    此时**持有信任的是老板（玩家）**，逼玩家去"读"NPC（看气泡、看行为，建自己的信任模型）。

  > 结论：无论做哪个方向，`mind` 都从"背景系统"升级为**核心玩法**——这就是它排第一的理由。
- **P8 【已定死】面板操作只改「世界真值」，不碰 NPC 知识**（§1.2，§6 红线 1）。
  玩家的手只能碰世界；NPC 的知识只能由**感知 / 传闻**进入。
  **禁止任何"全局同步 NPC 知识"的捷径**——违反则支柱 A 当场死。

### 待拍板

- **P2 "更好的资源与体验"具体是什么？** 更大的店是更赚钱，还是体验更好（能卖贵）？
  这决定经济是"规模线"还是"品质线"。
- **P3 店员的角色深度。** 店员是"会累的加速器"，还是"会跟顾客建立关系的人"？
  后者才咬合支柱 A，但成本高。
- **P4 时间尺度。** 一天多长？玩家经营一天还是快进一周？决定气泡的产生密度。
- **P5 气泡的信息量上限。** 满店顾客、每人一个泡，怎么不糊？分级 / 距离 / 重要度？
- **P7 面板打开时，世界时间走不走？**（§1.1）本文档倾向**继续走**，请拍板确认。

## 9. 与 `Vision.md` 的关系

`Vision.md` 是"人工社会实验场"的长期愿景；本文件是它的**商业游戏落地形态**：

- Vision 里"不同经历 → 不同认知 → 不同决策"，在本作里就是**不同顾客信不同的话**。
- Vision 里"不写恐慌抢购，让它自己出现"，在本作里就是**玩家的成功会自己招来人群**。
- Observatory（Vision §23）不删——它从"玩法"降级为"开发与调参工具"。

**本文件不推翻 Vision，它给 Vision 装了一个玩家。**
