# 消息传播 + 气泡 —— MVP

> 状态：**MVP 设计（待实现）**。上位：`docs/20260914/game.md §3 支柱 B`。
>
> 目标只有一个：**消息能传播 + 玩家看得见。**
> 其余（信任 / 应验 / 情绪 / 关系 / 计划 / 记忆日志 / LLM）全部推到 MVP 之后。
>
> 一句话：**一条带来源和置信度的记忆，在人与人之间以固定折扣扩散，扩散时在头顶冒出来。**

---

## 0. 反思：三份文档其实是一件事穿了三层皮

`docs/20260913/` 的四篇文档，在 MVP 里可以压成**一根线**：

| 文档 | 它真正在讲的 | MVP 取什么 | 砍掉什么 |
|---|---|---|---|
| `memory.md` | 记忆要能存"谁说的" | **`source` 一个字段** | Episode 环形日志、L2/L3 派生 |
| `mind.md` | 每个人对同一件事的相信程度不同 | **两级信任区间**（同址 / 路人） | verify、情绪、关系网、distress、信任的长期演化 |
| `semantic_event.md` | 把内部状态显示成一句话 | **`told` 一种 act** | 其余 7 种 act、语域、LLM 润色、校验闸 |
| `plan.md` | 让顾客到店有理由 | **暂时不动**（用现有硬编码计划表） | roles.json、自由块、plan_mult |

```text
MemItem(+source)  ──同地传递, believe×折扣──▶  另一人的 MemItem  ──▶  头顶气泡
    ①知识                    ②传播                       ③显示
```

**MVP 需要的不是三套系统，是这一根线。**

---

## 1. 全部 MVP = 三件事

### ① 知识 = 一行记忆，多一个来源

`npc/memory.py::MemItem` 增加：

```python
source: str = ""      # "" = 自己看到的; 否则 npc_id = 谁告诉我的
```

`_FIELDS` 与 `to_dicts()` 同步。**约 3 行。**

> 这是整条线的地基：没有 `source`，就不知道"这话谁说的"，气泡也就没内容。

### ② 传播 = 同地 + 空闲 + 说一件对方不知道的事

`world/engine.py::_notify_due(world, systems, npc)`（现为空壳）填成：

```text
对每个和我同地、且不是我的 NPC other（按 id 排序，保证确定性）:
    if rng.rand() >= tell_p × npc.tell_bias:            continue
    row = 我 believe 最高、且 other 没有、且 source != other 的一条记忆
    if row is None:                                      continue
    other.note(row.item_id,
               believe = row.believe × trust_between(npc, other),
               source  = npc.person_id, tick = now)      ← 写进对方记忆
    world.bus.publish(..., "told", ...)                  ← 供气泡显示
```

**信任只有两档 —— 这就是全部的"人际关系"：**

```text
trust_between(a, b) =
    同址(a.home == b.home 且非空)  → 0.9 ~ 1.0     同址：高保真中继
    否则                            → 0.4 ~ 0.7     路人：低通滤波
```

- **没有"家庭"这个对象，只有"住址"这个属性。** `home` 相等 → 高信任。
  `Person.home` 已存在（`config/scenes/*.json` 每个 npc 都写了 `home`）→ **零新数据、零新实体**。
- **同址不引入任何家庭语义**（不分夫妻 / 父母 / 子女）。它只是**分配住址时自动形成**的
  一个高信任簇。本文件不叫它家庭、不叫它住户，**只叫“同址”**。
- **一次抽定，不是每次现抽**：按两人 id 派生一个稳定值（零存储、可回放）：

```python
trust = 0.4 + 0.3 * frac(hash(sorted([a, b])))      # 不同址
trust = 0.9 + 0.1 * frac(hash(sorted([a, b])))      # 同址
```

  → 每对人一个固定值，玩家能观察到一个稳定的模式：**同址的人互相更信。**
- **不再需要 hop 折扣**：trust 就是折扣。同址 `0.95ⁿ` 衰减很慢，路人 `0.55ⁿ` 三手就死。
- 低于 `BELIEF_MIN`(0.3) 的不再传 → **消息自己停**。
- `tell_p` 已在 `Systems`，`rng` 必须来自 `systems`（确定性）。

> **为什么去掉“家庭”这个名词**（你提的理由）：一旦叫它“家庭”，玩家与代码都会期待它承担
> 家庭职责（谁做饭 / 谁买菜 / 谁带娃），而引擎并没有这些——结果就是“夫妻各自买饭回来
> 各吃各的”这类割裂。**去掉这个名词，就同时去掉了这个承诺和这个 bug 面。**
> 同址 = 一个布尔相等，职责为零。
>
> 这是 `plan.md §3.2` 那条原则的又一次应用：**代码不知道“是什么关系”，只知道“住址相同”。**
> 差异全在数据（场景里给谁分配哪个 `home`）。

**约 25 行。**

#### 为什么两个区间比"传几手打 0.6 折"好

上一版用 hop discount（每传一手乘 0.6）—— 那是**均匀衰减**，没有形状。
两档信任是**按社会结构衰减** —— 同样在衰减，但产生了结构：

```text
同址簇内部：每晚同处 → 信息快速对齐 + 几乎无损   →  同址簇 = 信息簇
同址簇之间：只能靠路人（低信任）→ 慢 + 失真       →  路人 = 桥
        ↓
城市自动分裂成若干"认知不同的同址簇"
```

**这正是 `Vision.md §15` 想要的现象（不同社区拥有不同认知），且不用写一行"社区"代码。**
只定义了"谁跟谁住一起"。

### ③ 显示 = 头顶一句话

**完整方案见 `docs/20260914/bubble.md`。** 要点：

- **后端决定说什么**，快照带 `bubble` 字段，前端只画、不计算。
- 气泡是**瞬时事件**（活 ~40 ticks），不是 `activity` 状态。
- 新建 `bubble_layer.gd`，用 `draw_style_box` + **屏幕坐标 + 固定像素字号**，**零节点**。
- 已拍板：**挂听者**；MVP **不可点**。
- 文案极简模板：`told → "听说{名字}{价格}块"`（不接 LLM）。

## 2. 明确不做（MVP 之外）

| 不做 | 为什么可以不做 |
|---|---|
| `trust` 的**演化** / `Relation` / `Mind` 类 | 信任只需要两个**静态**区间，不需要一个会变的系统 |
| `verify` / 应验 / 掉信任 | 信任不降 → 不需要应验 |
| 情绪 / 好感 / 关系种类（朋友/敌人/家庭） | 关系只需要"同址 / 不同址"一个布尔判定，不需要"关系"这个概念 |
| `Episode` 环形日志 | 只要"那一行记忆"够用 |
| `plan.md`（roles / 自由块 / plan_mult） | 现有硬编码计划表还能跑 |
| `semantic_event` 的 8 种 act / 语域 / LLM 润色 | 一种 `told` + 一种 `need` 就够展示 |
| 听觉半径 | 先按同 `location` |

## 3. 为什么砍完还成立

1. **消息会传** —— 你要的"传播"达成，且可观察。
2. **`believe` 按信任打折** —— A 亲眼看到（1.0）；B 从路人听说（× 0.4~0.7）；
   同址的人告诉他（× 0.9~1.0）。**"每个人知道的不一样、信的程度不一样"** 就是全部核心视觉。
3. **"已知不说" + 折扣** —— 消息传几手自己就停（`mind.md §7.4` 已论证）。
4. **信任是静态的 → "人人没信任"的坍塌根本不会发生。**
   坍塌的根因是 `verify` 不断把 trust 往下扣；MVP **没有 verify**，trust 永远是抽定的那个值，
   只在区间里不动。等 `verify` 作为插件加回来时，再套那三条修正（消息带时效 / verify 挂后果 / trust 有回归）。
5. **复用已有一切** —— `home` / `believe` / `remember` / 半衰 / `EventBus.audience` / 气泡组件 / `tell_p` 全是现成的。

## 5. 验收（看得见，不是单元测试）

> **玩家把苹果从 10 改到 8：**
>
> 1. NPC A 进店 → 感知到新价 → 头顶冒 **「苹果 8 块？」**
> 2. A 回到住址 → 同址的另一人 D 头顶冒 **「听说苹果降价了」**，且 D 的 `believe` 接近 A。
> 3. A 在路上遇到路人 B → B 头顶冒 **「听说苹果降价了」**，但 B 的 `believe` 明显更低。
> 4. 第二天，C 出现在店里；B 可能没来。
> 5. 玩家能点任一人，看到记忆里那一行 **`source = A`**。

另外四条硬指标：

- `test_replay.py` 仍通过（`rng` 来自 `systems`）。
- 跑一天，若无人改价，`told` 事件数为 **0**（没有无中生有）。
- 同一条消息不会来回传（`source != other` + "对方已知不说"）。
- **同址两人之间传的 `believe` 幅度 > 路人之间传的**（两级信任生效）。

## 6. 唯一的真实缺口：顾客进店后看不见

`godot/scripts/render/entity_layer.gd` **只在路上画 NPC**（「人在建筑里不画圆点，否则点房子会误选到人」），
所以顾客一进店，玩家就看不见他 → 气泡没有附着点。

| 方案 | 内容 | 工作量 |
|---|---|---|
| **(a) 路上传播**（推荐先做） | 两个 NPC 在路上遇见 → 冒泡 | 几乎零新渲染，先证明**管线** |
| (b) 店内传播 | 先让 NPC 进店后仍可见，再做店内气泡 | 多一块渲染工作 |

**(a) 能证明全部机制**，只是把展示位置从店内挪到路上。管线通了，把气泡搬进店里是纯 UI 活。

## 7. 插件位（MVP 之后往这根线上挂什么）

按性价比排序，**每一条都是挂在同一根线上的插件，不重写**：

1. **`verify`** —— 到店发现不符 → trust **第一次会变**（掉）→ 气泡「王哥骗我」。
   （**"骗"的玩法从这里开始；也是唯一需要把静态 trust 升级成可变 trust 的一步**）
2. **信任连续化** —— 从"两个区间"扩到"每人每对一个值 + 好感/亲密"。
   前一步（静态派生）已经为它留好了位置。
3. **店内气泡** —— 顾客进店可见 + 气泡（支柱 B 的完整形态）。
4. **`plan`(F1/F2)** —— 让顾客到店有时间规律，传播有节奏。
5. **`Episode`** —— 让玩家能追问"这印象哪来的"。

> 注意：**`trust` 已不在插件列表** —— 两档信任已经是 MVP 本体的一部分。

**每一层都只在 `①知识 / ②传播 / ③显示` 三段里替换一段，不改骨架。**
