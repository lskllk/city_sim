## 0. 定位收缩：推翻 0913 的「计划主导」

### 0.1 原设计

```text
计划表主导 = 强制块（三餐/睡觉）+ 自由块
utility    = 仅在 fallback_need = 0.9 时兜底的安全网
```

### 0.2 错在哪

| 问题 | 后果 |
|---|---|
| 计划表由**全局时钟**驱动 | 所有人 12:00 一起饿 → **一起出门、一起进店**（扎堆） |
| 计划表替 utility 干了它该干的事（吃/买/玩） | **涌现被压制**，世界变钟表 |
| 「自由块」的存在理由 = 在计划表框架里给 utility 留位置 | 一旦 utility 主导，**它整块多余** |

### 0.3 新原则

> **PLAN = 对社会的时间承诺**（有人在等、违约有后果）。
> **utility = 其余一切。**

| 归属 | 内容 |
|---|---|
| **PLAN** | 上班 / 上学 / 约会 / 值班 |
| **utility** | 吃 / 买 / 玩 / 社交 / 回家 / 睡觉 |

## 3. 候选收集放开 + 删除 `REFLEX_SIGNALS`（"utility 主导"的开关）

**现状**（`npc/brain.py::_gather_candidates`）：

```text
if sig not in REFLEX_SIGNALS or value <= 0 or believe < BELIEF_MIN: continue
need = 1 - signal
if need < fallback_need(0.9): continue
```

**问题**：凡**不在白名单里**的信号**永远产生不了候选** → 睡眠 / 购物类行为都跑不起来。

**改成**：

```text
候选 = 记忆里所有 afford 非空 且 value > 0 且 believe ≥ BELIEF_MIN 的行
阈值 = need_floor（建议 ~0.15）：低于此不动作
排序 = eff（含成本项）；utility_threshold 给一个正的小值，滤掉琐碎行为
```

### 3.1 顺带删掉 `REFLEX_SIGNALS`（决定）

**它已经不承担任何必要职责**，而它牵连的不止一个常量：

| 它现在负责 | 删掉后由谁负责 |
|---|---|
| 哪些信号产生候选 | `need_floor`（**数值**，不是白名单） |
| 哪些需求能**硬中止**计划（抢占） | **不需要** —— 计划只是偏置（不是命令） |
| reflex 轨优先于 plan 轨 | **不需要** —— 只剩一轨：utility 打分 |

**核心理由**：

> 一旦计划只是**偏置**（不是命令），就**没有“要抢占的计划”**。
> 憋不住 vs 上班：`need^power`（power=3）下，`0.9³ = 0.729` vs `0.3³ = 0.027`，**差 27 倍**。
> **紧急度本来就由数值表达，不需要一个白名单轨道。**

**可以一并简化的东西**（待评估）：

- `person.decide` 的**双轨**（`_reflex_goal` / `_plan_goal` 优先级）→ 单轨
- `engine.py::_can_preempt` / `_preempt`
- `world/interaction.py` 的 `suspend` / `resume`（reflex 抢占的高保真恢复）
- `Decision.source` 的 `"reflex" / "plan"` 区分可能一并简化

### 3.2 但有一个东西**必须保留**

**交互的「可中断性」（`interruptible`）** —— 它是“**这个交互能不能被打断**”，
与“**哪些信号算紧急**”正交。删的是后者，**不是前者**。

### 3.3 风险与分步

- **抖动 / 来回横跳** → 需要**承诺 / 迟滞**：一旦开始就做完，除非效用差距极大。
- **测试会挂**：`tests/test_plan_interrupt.py`、`tests/test_behavior_soak.py`。
- 失去“濒死保命”的硬保证 —— 但 `need^power` 在数值上其实更强。

> ⚠️ **分两步走**：
> ① 先只删白名单过滤 + 放开阈值，跑 7 天 soak 校准 `need_floor`（本次最高风险参数）；
> ② 再删双轨仲裁（更大的一刀）。

## 4. 成本模型（比价 / 比距离 / 顺路）

```text
cost = price × qty
     + time_value × travel_ticks
     + κ × price × (1 − believe)          # 不确定的便宜要打折

eff  = (urgency^power × value × personality × believe) / (1 + λ × cost)
```

- **比价** = `price` 项。
- **比距离** = `travel_ticks` 项。
- **「顺路」自动涌现** —— 不写"顺路"逻辑，路过的那家时间成本低，自然更容易被选中。
- `κ` 项让"听说便宜"不如"亲眼看到便宜"可靠 → **传播层获得经济后果**。

原来被划到"不在本次范围"的 **F3 成本项，在 utility 主导下必须现在做。**

## 5. PLAN 保留什么

### 5.1 承诺（数据，不是代码）

新增缩小版 `config/roles.json`：

```json
{
  "worker":  {"anchors": [{"goal": {"kind": "work"}, "at": "09:00", "until": "18:00", "loc": "@affiliation"}]},
  "student": {"anchors": [{"goal": {"kind": "school"}, "at": "08:00", "until": "15:00", "loc": "@affiliation"}]},
  "unemployed": {"anchors": []},
  "retired":    {"anchors": []}
}
```

`@affiliation` 是**解析器**（失业 → 解析失败 → 该锚点自动不生成），沿用 `20260913/plan.md §3.2`。

### 5.2 派生预备（不迟到靠预留，不靠门禁）

- **出发时刻 = 承诺时刻 − travel_cost − 个体提前量**
- `plan_mult` 随临近陡增（软保证）
- 计划可硬中止（现有 `Decision.source = "plan"`）

### 5.3 违约 = 后果，不是门禁

迟到 / 早退 → 记录 → **扣钱 / 信任↓** → 极端情况被辞退。
（对齐 `20260910` D2。）

### 5.4 错峰（让人不扎堆）

| # | 手段 | 说明 |
|---|---|---|
| 1 | **个体相位偏移** | 锚点时间 + `hash(id) → 0..90min`。王哥 12:00，李四 12:37 |
| 2 | **个体库存差异** | 各家耗尽时间天然不同 → 采购时刻天然错开 |
| 3 | 出发 = 承诺 − 路程 − 提前量 | 已有 `travel_cost` 预留 |
| 4 | 承诺只占少数时间，其余全是 utility | 由个体状态驱动，天然发散 |

> **集中不是 bug**：自然错峰 = 基线人流（店主可规划产能）；
> 玩家促销制造的集中 = 玩法。**不做"禁止扎堆"，做"默认错峰 + 允许玩家制造高峰"。**

### 5.5 承诺怎么驱动与保持 —— 「困得不行但得上班」

只剩一条决策轨（无 reflex / 无双轨），所以承诺**不能靠“抢占”维持**。三段机制：

| 阶段 | 机制 |
|---|---|
| **① 去上班** | 承诺给出一个**由时间派生的紧迫度**（离迟到越近越高）→ 和需求候选**同一张表**竞争，把“去公司”推成最高分 |
| **② 在岗** | 人**已经在做着**（进行中的交互 = incumbent，天然迟滞）→ 要离开，竞争候选的效用必须**压过一个 `breach_cost`**（“走人要扣钱”，**此刻就知道的价格**） |
| **③ 下班** | `until` 到点 → 承诺窗口关闭 → `breach_cost` 消失 → 睡觉自然胜出 → 回家睡 |

**为什么“困得不行”压不过上班**：

```text
energy 低                    → 睡觉的效用【有上限】（≈ 1 × value）
只要 breach_cost > 那个上限   → 日常困【永远走不了】
但 breach_cost 是【有限】的   → 真撑不住时能走 → 认罚
```

> ⚠️ **补丁（必须有）**：`breach_cost` 必须**随 `hp` 衰减**：`breach_cost × f(hp)`
> —— **hp 越低，违约金越不值钱（命比钱重要）**。
> 否则 reflex 删除后，“熬”没有任何东西能拦住 → NPC 会**在工位上累到死**。
> 零门禁，纯数值。

**结果阶梯（零门禁）**：

| 状态 | 行为 |
|---|---|
| 有点困 | 熬，产出略降 |
| 很困 | 熬，产出明显降，`reason = "困但得干完"` |
| 极困，体力还够 | 熬（`breach_cost` > 睡觉效用） |
| **极困 + 体力也崩** | **走** → 扣钱 + 信任↓ → 回家睡 |
| 下班了 | 窗口关闭 → 回家睡 |

**白拿的三样**：

1. **迟到**：同一套机制（起不来 → 迟到 → 违约成本）。
2. **气泡**：`reason = "困死了，但不能走"` —— 这正是语义层该显示的东西。
3. **个体差异**：`conscientiousness`（尽责）调 `breach_cost`，**划水的人更容易走**。

> ⚠️ **一个必须同时定的点**：承诺必须能**驱动**动作，而不只是**偏置**。
> 因为“上班”本身**不满足任何生理需求**（它产出钱，不是信号）。
> 所以承诺以「**时间派生的紧迫度**」形式参与打分 —— 它只是**另一种“想”**，不是“必须”。
> （与“不门禁”不矛盾：**紧迫度可以被打败**。）

## 6. 囤货：目标存量模型

### 6.1 三个主体（拆开，避免"有需求的组"）

```text
容器实际存量  ∈ 家     （共享事实：谁都能看见，会消耗）
目标存量      ∈ 个人   （偏好：由人格 thrift 决定 —— "我家该常备 N 个"）
缺口 = 目标 − 实际      → 这个人的「预期需求」
```

### 6.2 公式（与睡觉同构）

```text
need_now    = 1 − signal
need_future = f(目标存量 − 实际, 消耗速率, 补货耗时)
urgency     = max(need_now, w × need_future)
```

- **"谁去买"不需要调度**：谁的前瞻效用最高谁去。
- **"家里有人有记忆能满足"自动成立**：每个人用**自己的记忆**算候选。

### 6.3 为什么不做「home 有需求 → 发任务」

| 该方案 | 问题 |
|---|---|
| home 有 needs | 又造了一个**有需求的组** = 换皮的家庭概念 |
| 有需求 → 发任务 | 立刻需要 **"派给谁"** 的调度系统（一个可以**永远不做**的系统） |

且 `Vision.md §11` 已明确否掉脚本式囤货：
> 囤货 ≠ `if shortage: buy_many()`，而是"一个有限理性的资源主体对未来不确定性的反应"。

### 6.4 白拿的洞察

> **一个家的采购能力 = 成员记忆的并集；但行动只能由"知道的那个人"发起。**

→ 广告 / 招牌能"让原本不知道的人知道" = **给这个家新增采购能力**（见 `game.md` 支柱 A 的落地）。

### 6.5 重复购买

自限（库存高了就没人再买）、lumpy（对店主是好事——大单）。
**先不做去重**（去重会引入共享状态）。

## 7. 睡眠：单信号 `energy` + 昼夜衰减

### 7.1 决定：不拆信号

原方案是拆成 `energy`（体力）+ `alertness`（困倦）两根正交轴。**已放弃**，理由：

> 拆的两个理由都被 **删除 `REFLEX_SIGNALS`** 带走了：
> - `alertness` 不进 reflex（避免硬中止工作）→ 没有 reflex 了，自动成立
> - `energy` 当"硬保险" → "硬保险"变成"`energy` 归零 → `hp` 掉"，一个信号够
>
> **拆的真正目的只是"让 NPC 在夜里想睡"，一个信号也能做到。**

### 7.2 机制

```text
energy 每 tick 衰减 × 昼夜系数           # 夜里掉得快 → 夜里想睡
       额外 × activity_mul               # 干活 / 走路掉得更快
energy 归零 → hp 开始掉（现有行为，保留） # "累垮"
睡觉 → 恢复 energy（现有 bed.affordances = {energy: 0.7}，不用改）
```

**一个信号同时表达"困"和"累"**：

```text
熬夜 → energy 掉得多 → 第二天更低     ← 睡眠债天然在里面
```

因为 `energy` 是**历史行为的积分** → "决策线性、有历史性"自动满足。

### 7.3 收益对照

| 原收益 | 单信号 |
|---|---|
| 睡眠从编排变驱动 | ✅ 昼夜曲线 |
| "上班困死跑回家" | ✅ 由 `breach_cost` 拦（不再需要 reflex 区分） |
| 惩罚分层 | ✅ 变成"累了慢"（少了"困 vs 累"） |
| 两条独立历史 | ✅ 一条积分够用 |
| **两个玩法杠杆**（咖啡 / 饭） | ❌ **丢失** → 延后 |
| 老板自己也成立 | ✅ |

**只丢"两个玩法杠杆"和"困/累区分"。** 将来真需要时再拆 —— 那时是**加**，不是**改**。

### 7.4 顺带省掉的改动

- **床的数据不用改**（保持 `affordances: {"energy": 0.7}`）
- **不新增信号**（`SIGNALS` 保持 `energy / hunger / bladder / hp`）

### 7.5 已定口子

| # | 口子 | 决定 |
|---|---|---|
| 1 | 昼夜数据 | **控制点插值**（进 `sim.toml`） |
| 2 | `_gather_candidates` | **放开**（同 §3） |
| 3 | 前瞻 | **MVP 不做**（睡觉效用只看 `need_now`） |
| 4 | 睡醒条件 | **睡满 `duration_ticks` 自然醒** |
| 5 | `hp` | `energy` **保留**参与 `hp_decay`（= "累垮"，不是"困死"） |

### 7.6 数值起点（待 soak 校准）

```text
一天 1440 tick；目标睡 8h(480)。
想让 energy 在约 16h(960 tick) 清醒内从 1 掉到 ~0.5（刚好把人拉去睡）
→ 平均衰减 ≈ 0.5/960 ≈ 0.00052 /tick
白天更低（~0.0003），夜里更高（~0.0009）——控制点插值
```

## 8. 惩罚 = **状态调制产出**（不做门禁）

| ❌ 违规扣分（编排） | ✅ 状态调制产出（涌现） |
|---|---|
| 需要"裁判"判断违规 | 不需要裁判，状态自己说话 |
| 离散、突兀、可被看穿是规则 | 连续、可预期、可解释 |
| 例：熬夜扣 10 块 | 例：困 → 干活慢 → **产出少 → 工资自然少** |

```text
产出       = 基础产出 × f(energy)
迟到/早退  = 计划违约 → 扣钱 + 信任↓        （复用 plan 违约）
长期欠债   = energy 崩 → 生病 / 辞退
```

**惩罚必须回写状态**（钱少了 → 买不起东西 → 更穷）→ **闭环**。

> 泛化原则：**所有惩罚都做成"状态影响表现"**（困了慢、饿了慢、病了慢、心情差易出错）。
> 这样永远不需要一个"惩罚系统"，只需要**表现是状态的函数**。

### 8.1 生命（`hp`）三态

**现状代码已经是这个形状**（`npc/person.py::heartbeat`），只缺“中间带”：

```text
hp 下降   hunger == 0  或  energy == 0
hp 不动   其他（例：hunger = 0.4，吃了但没吃饱）
hp 上升   hunger ≥ 0.5  且  energy ≥ 0.5
```

- **膀胱（`bladder`）不参与 `hp`**（现在已经如此，保持）。
- **中间带必须有**：否则咬一口饭、睡 1 tick，`hp` 立刻开涨 → “饿死”永远发生不了。
- 阈值 `0.5`（= “吃饱 / 睡够”），进 `sim.toml` 可调。

### 8.2 `hp < 50%` → 计划失去拉力（等价于“打破 PLAN”，但不用门禁）

```text
hp < 0.5  →  plan_mult   = 0      # 计划不再有任何拉力
             breach_cost = 0      # 离岗不再有代价
```

| hp | 结果 |
|---|---|
| ≥ 50% | 计划有拉力 + 离岗有代价 → **熬** |
| < 50% | 计划无拉力 + 离岗免费 → **先满足自身需求** |

- 效果**等价于“打破 PLAN”**，但是“**命比钱重要**”这条原则的自然结果，不是硬分支。
- 这也是 §5.5 那个补丁 `breach_cost × f(hp)` 的**具体化**：`f(hp) = 0 当 hp < 0.5`。
- 玩家（老板）会看到员工快撑不住时自己走人——**这不是 bug**。

## 9. 判据：什么算「编排」

> **数据里能不能删掉所有「时刻 → 行为」的映射？**

| 类型 | 例子 | 处置 |
|---|---|---|
| **编排**（时刻→行为） | "22:00 去睡觉" | **删** |
| **生理/环境约束** | "夜里困得快"、"距离远耗时长"、"店关门了" | **保留**（合法涌现燃料） |

同类的合法约束还有：昼夜节律、价格、距离、关门时间、工作承诺。

## 11. 铁律

> **第 0 铁律（定死，最高优先级）：知识边界。**
> **玩家的手只能碰世界，碰不到 NPC 的脑子。** 经营动作只写**世界真值**；
> NPC 的知识**只能**由**感知**（`perceive_into`）或**传闻**（`_notify_due`）写入。
> **禁止任何“全局同步 NPC 知识”的捷径**。
> 读侧 `decide` 只读记忆（已有）+ 写侧记忆只能由感知/传闻写（新）→ 架构上不可违反。
> （见 `docs/20260914/game.md §1.2 / §6 红线 1`）

1. **PLAN 只做承诺**，其余全归 utility。
2. 计划只**偏置**，不**门禁**；违约走**后果**。
   - 承诺以「**时间派生的紧迫度**」参与打分（不是指令）；
   - 保持承诺靠 **`breach_cost`**（一个当下的价格），不靠抢占轨；
   - `breach_cost` **随 `hp` 衰减**：`hp < 0.5` 时 `plan_mult = breach_cost = 0`
     （命比钱重要，否则会“累死在工位”）。
3. `npc/` 不 import `world`。
4. **日程生成确定性**（同 seed 同日 → 同日程）。
5. **没有 reflex 白名单，没有双轨仲裁** —— 紧急度只由数值（`need^power`）表达。
6. **没有归巢规则**（`home_bias` 已删）——回家只能是效用的结果。
7. **没有 `safety`** —— 评估后判定它让系统变复杂；不引入。
8. 囤货与睡觉都走**同一条 `eff` 公式的 `need_future` 项**，不新增系统。
9. **惩罚 = 状态调制产出**，不写"违规扣分"。
10. 数据里不出现「时刻 → 行为」的映射。
