## 一、一句话

> **一个视野有限的人，在一座小城里靠关系和情报做买卖；他靠别人记得他活着，最后要么穷死，要么自己走了。**

内核已经给你的：**NPC 不看全知地图，只靠自己记得的东西活**。
这条约束长出了信息差、传闻、误判、探索——**游戏的全部玩法都是它的推论**。

## 二、架构师的认知：这个游戏的骨架

### 2.1 一条主链

```
声誉  →  钱  →  食物  →  活着
(别人记得你)  (你买得起)  (你吃得上)
```

**不是"为了赢而赚钱"，是"为了不饿死而赚钱"**（死亡只有一条路：缺钱饿死）。
而赚钱唯一可持续的方式，是别人记得你、愿意来。**题眼和生死绑在同一条链上。**

### 2.2 三条线，唯一兑换物是时间

```
钱   只能买: 时间（雇人腾出你自己）· 生产资料（工位 / 机器）
声誉 只能挣: 在场 · 有货 · 价格公道 · 好好搭话          ← 钱买不到
信息 只能挣: 打听 · 观察 · 雇人替你看（仍是有损二手）    ← 钱买不到
```

**钱和声誉是两条不能互相兑换的线。** 唯一的兑换物是**时间**。
而雇人有个副作用：**站在那个工位上挣到的脸面，是雇员的，不是你的。**

> 这条是整个游戏的张力来源。任何时候有人提出"某个东西可以用钱直接买到声誉/信息"——那是在拆主链。

### 2.3 两条红线 + 一条纪律（不可违反）

| 类型 | 内容 | 落点 |
|---|---|---|
| 红线（内核已有） | **决策只读记忆**，不查世界 | `tools/check_imports.py` + `tests/test_import_layers.py` |
| 红线（新增） | **衰减只允许丢精度，不允许造新信息** | `npc/memory.py` · `game/lines.py`（表达） |
| 纪律（新增） | **面板上每个字段，都必须能回答"发行版玩家从哪儿合法知道它"**。答不出的字段不许上界面 | `gateway/snapshot.py` + UI |

这条纪律是**有限视野的唯一守卫**。它比任何"注意别泄露"的口号都管用——**因为它是可以逐字段检查的**。

### 2.4 一个纪律的推论：上帝版 / 发行版是同一套 UI

```
上帝版  = 面板直接读引擎（点谁看穿谁）      ← 测试用
发行版  = 面板只读【账本 + 玩家记忆】        ← 发行用
两者是同一套 UI，只换数据源。
```

**推论**：如果一个字段只有上帝版能给，那它**不是 UI 功能，是调试器**——它不该被设计成"玩家操作"。

### 2.5 一个形状：没有输赢

```
没有胜利宣告 · 没有失败画面 · 但死亡真实存在（且只有一种：缺钱饿死）
唯一的"完成"：系统在你够格时【把门打开】，走不走由你
```

这带来一条硬要求：

> **死亡必须可复盘。** 账本要能回答"我是从哪天开始亏的、王阿姨是从哪天不再来的"。
> **账本 = 声誉的可读器 + 玩家的讣告 + 验尸报告。**

### 2.6 分层：什么"深"、什么"皮"

| | 深（不许动） | 皮（随便换） |
|---|---|---|
| 内核 | 认知/世界的边界 · 决策只读记忆 · 确定性 | — |
| 传播 | 事实/传播/表达 三层 · 精度衰减只丢不造 | 模板池的措辞 |
| 时钟 | tick 驱动 · 快进=跳到 | 倍率数值 |
| 表现 | — | 2D↔2.5D · 素材 · UI 风格 |
| 智能 | 经营决策接口的形状 | 驱动实现（规则 / LLM） |

## 三、系统清单与依赖顺序

```
① 账本（人名册 + 讣告 + 验尸报告）        ← 发行版唯一的信息面板
② 精度衰减器（remember 分桶，只丢不造）    ← 传播系统的核心
③ 经营决策接口（一接口两驱动）             ← 解锁无头平衡测试
④ LLM 驱动 + transcript 落盘 + schema 校验 ← 确定性与人味并存
⑤ 造人器（结构程序 / 人味 LLM / 冻结成数据 / 支持局中调用）
⑥ 开局初始化（外来者 + 种子关系 + 隔壁对手）
⑦ 减员可感知（账本按"上次来是几天前"排序）
⑧ 模板池表达维度表 ★                       ← 先于⑤，因为它约束⑤
```

**依赖关系**：
```
⑧ 维度表 ──┐
① 账本  ──┼─→ ② 精度衰减器 ─→ ③ 经营接口 ─→ ④ LLM 驱动
           │                                    └─→ ⑥ 开局 · ⑦ 减员
           └─→ ⑤ 造人器（只依赖 ⑧ 和对字段形状的约定）
```

## 四、团队分工

> **硬事实：只有 1 个程序。** 排期必然串行。
> 所以分工的原则是：**让另外 3 个人的产出尽量不依赖代码**。
> 好消息：这游戏最难的几件事（造人、维度表、验收标准）**恰好都不用写代码**。

### 架构师 ★ 杠杆最高

| | 内容 |
|---|---|
| **现在就能开工** | ① **模板池表达维度表**（话多/话少 · 乐观/刻薄 · 直接/爱打听 · 抠门/大方 …）——它同时是造人器的输出维度<br>② **契约**：账本字段 · 经营命令集 · LLM 输入输出 schema<br>③ **参数表**：就业/工资两颗旋钮 · 记忆半衰 · 信任折扣 · **精度档位阈值** · 保质期 · 好感回升，每条附"为什么"<br>④ **判定条件**：够格开门的条件 · 减员感知的窗口 · 开局初始状态 |
| **什么样算完成** | 程序照着能直接写、不用再问；测试能照着写断言 |
| **不该做** | 不要自己抢程序写代码 |

### UI 设计 ★ 最该先做

| | 内容 |
|---|---|
| **现在就能开工** | ① **账本**：人名册 + 讣告（谁·何时·买了什么·第几次来·上次来是几天前）<br>② **打听界面**：问什么 / 答什么 / 来源与时间 / 他愿不愿意说<br>③ **经营面板**：定价 · 进货 · 雇人 · 排班 · 今天露不露面 —— **必须与 AI 的命令集一一对应**<br>④ **快进控件 + 结束摘要**<br>⑤ **一份"什么该给玩家看 / 藏"的说明** ← 数据源纪律的落地文档 |
| **什么样算完成** | 能回答"玩家为什么看不见全貌"；每个控件都能对上一条命令或一个合法数据源 |
| **不该做** | 先别做美化（风格未定）；别把上帝版的面板当玩家界面设计 |

### 美术

| | 内容 |
|---|---|
| **现在就能开工** | ① 2D 俯视素材：建筑 / 地面 / 道路 / 工位 / 货物 / 小人<br>② **Demo 的 15 张脸 + 名字**（顺手起名、定长相）<br>③ **一套"显著特征库"**（发型 / 体型 / 配饰 / 职业道具）← 造人器"可区分性 > 随机性"的素材基础 |
| **什么样算完成** | "占位但风格定下来"（代码不需要美术也能跑） |
| **不该做** | 别做等距 / 3D（已定 2D） |

### 测试 ★ 形态特殊

| | 内容 |
|---|---|
| **现在就能开工** | ① **红线测试清单**（四条，可写成断言）：<br>&nbsp;&nbsp;· 决策只读记忆<br>&nbsp;&nbsp;· 衰减只丢精度、不造新信息<br>&nbsp;&nbsp;· 面板字段必有合法来源（数据源纪律）<br>&nbsp;&nbsp;· LLM 输出不含骨架之外的新断言（schema 校验）<br>② **长局可信度**：跑 N×30 天回答"这世界说得通吗"（`tools/sim_report.py` 现成）——**重点是就业与工资那两颗旋钮**<br>③ **死亡可复盘**：能不能从账本回答"我从哪天开始亏的"<br>④ 契约测试清单（每个字段都在） |
| **什么样算完成** | 能说出"这次改动让世界变得可信 / 不可信" |
| **不该做** | 不要只点按钮找 bug |

### 软件工程师 ★ 关键路径

| | 内容 |
|---|---|
| **先做** | `0` **契约落成代码** → 解锁所有人<br>`1` **账本**（发行版唯一数据源）<br>`2` **经营决策接口**（一接口两驱动）+ 规则驱动 + 无头跑<br>`3` **玩家面板接进同一条接口**<br>`4` 上帝版 / 发行版数据源切换<br>`5` 开局初始化 · `6` 精度衰减器 |
| **落点（参考）** | `core/types.py`（命令/通知）· `npc/planner.py`（决策插槽，现在 `None`）· `npc/memory.py`（精度衰减）+ `npc/semantic.py` / `game/lines.py`（说什么 / 怎么说）· `world/econ/company.py` + `market.py`（经营动词）· `gateway/snapshot.py` + `server.py`（账本与快进） |
| **什么样算完成** | 场景里点一下能走 / 买 / 用；AI 老板能无头跑完 N 天 |
| **不该做** | 不做内容 · 不做美术替换 · 不做界面美化 |

### 依赖与关键路径

```
架构师(维度表 + 契约) ──→ 软工(地基) ──→ UI / 美术 / 测试 并行收口
                              │
                              └─→ 关键路径: 契约 → 账本 → 经营接口 → 玩家面板
```

## 五、风险清单

| # | 风险 | 处置 |
|---|---|---|
| 1 | **经营决策接口横跨 `npc/` 与 `world/` 的边界**（公司账在世界侧，记忆在认知侧） | 必须设计成一个**窄口**；别为了省事让认知侧去查世界，那会破红线 |
| 2 | **表达维度 ≠ 生成维度** → 生成出来的性格在游戏里说不出来 | 先定 ⑧ 维度表，再让造人器只在这些维度上编人 |
| 3 | **Demo 只在上帝版验证"过时"** → 发行版可读性无人验证 | 已登记为已知风险；手机是唯一解药 |
| 4 | **就业 / 工资两颗旋钮**是全城最重要的数值（README 的"60 天全灭"根因） | 测试用长局跑回来；架构师定初值 |
| 5 | **只有 1 个程序** → 排期串行 | 别的线尽量产出不依赖代码的东西（维度表 / 线框 / 素材 / 验收清单） |
| 6 | **快进 = 跳到 撞 LLM** | 快进区间降级到规则驱动；LLM 只在玩家视野内触发 |
| 7 | **人口只减不增** → 每局轨迹单调衰减 | 已接受（外部市场闭环，饿不死）；靠"减员可感知"把衰减变成叙事，而不是背景噪音 |

## 六、现在就能并行开工的四件事

```
架构师  模板池表达维度表 + 契约（这两个不写完，别人只能等）
UI      账本人名册 / 讣告 的线框（最重要的一张图）
美术    15 人 + 建筑占位素材 + 显著特征库
测试    四条红线的断言清单 + 长局可信度的判定标准
```

> **一句话给全队**：这游戏做不做得成，不看你能加多少系统，
> 看你能不能守住一句话——**"发行版的玩家，凭什么知道这件事？"**
