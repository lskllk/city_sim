# 美术方向（Art Direction）

> 角色：UI / 信息设计 兼美术方向。**这份文档是给美术同学开工用的**。
> 上游：[UI 与信息设计](ui-design.md) · [游戏构思](game-concept.md)（决定 #5：画面 = 2D 俯视）
> 原型：`proto/ui-prototype.html`（里面是**代码画的占位美术**，每个位置都能换成真素材）
>
> ★ **已经有一套可运行的资产了**：`art/`。
> 它把这套规则写成了 `art/style.json`（色板 + 6 条规则），用 `art/gen.mjs` 生成
> 174 个 SVG（地面/道路/装饰/建筑/人物/特效），一条命令出全套：
> `bash art/build.sh` → 资产 + 校验 + 联络表 `art/out/preview.html`。
> **本文件是"为什么这么画"；`art/README.md` 是"怎么改画风/加人"。**
> 美术接手时按本文 §五/§八 的规格交图替换即可（文件名、尺寸、锚点、图层都已定死）。

---

## 〇、一句话

> **世界是彩色的城市，你的认知是贴在它上面的纸片。**

地图是有颜色的、有纹理的 2D 俯视小城；而所有**信息**（名字、价格、来源、褪色）都是**纸片**贴在上面。
这个对比不是审美选择 —— 它是玩法本身：**城市是真的，你知道的那部分是纸做的、会过时。**

---

## 一、视角与网格

| 项 | 定 |
|---|---|
| 投影 | **正俯视**（top-down），决定 #5。不做等距、不做 3D |
| 城市的"厚度"用**落影 + 立面揭示**做，不用透视 |
| 逻辑网格 | **1 格 = 32 px**（@1x） |
| 世界尺寸 | 64 × 44 格 = **2048 × 1408 px**（一个小镇） |
| 建筑 | 按整格对齐；直接盖在格子上 |
| 人 | 1 格宽（形象约 20 × 28 px），脚底对齐格中心 |
| 导出 | **@1x 和 @2x 两套**（Retina）。命名见 §八 |
| 相机 | 0.5× ~ 3×。0.5× 时建筑贴图要还看得出是房子（不要糊成色块） |

**为什么正俯视**：决定 #5 已经写死，而且它让"2D↔2.5D 只是换投影层，可逆"成为真话 ——
所有坐标是平面网格，换投影只改渲染时的 y 缩放，不动任何逻辑。

## 二、色板

地图是**饱和的、有质感的**；UI 是**安静的纸**。两者不许互相抢。

### 城市（地图）
```
沥青路面    #4c4a4a      人行道    #b8b3a6      路缘/标线  #e9e5da
草地        #6d8a52      草地深    #5f7a47      泥土        #a89476
水          #5a7f96
屋顶·砖     #8c5b48      屋顶·灰   #6b7176      屋顶·瓦     #7a6a5a
墙·米       #d6c6a5      墙·浅     #c9b795
树          #4f7a45      树深      #3d6236
窗（白天）  #8fa3ad      窗（夜）  #ecc579
```

### UI（面板）—— **保持不变，别跟着地图走**
```
纸底   #f7f4ee    次级 #efebe1    线 #ded7c8    墨 #26221c    次墨 #7a7264
强调   #b4552d（钱 / 警告 / 选中）   好 #4a7358
```

> ⚠ **UI 不许为了"配地图"加饱和色。** 地图越热闹，UI 越要像一张安静的纸 ——
> 因为纸代表你的认知，而认知是这个游戏里唯一稀缺的东西。

## 三、图层与交付物

```
L0  地面     草地/泥土/广场/水      可平铺底 + 地块覆盖
L1  道路     沥青 + 人行道 + 标线    模块化 tile（直/弯/十字/T/尽头）
L2  地块装饰  树·灌木·长椅·路灯·垃圾桶·停着的车   散布小贴图
L3  建筑     屋顶 + 立面揭示 + 门口 + 招牌底      每栋一张
L4  实体     人（走/站）+ 玩家       SpriteSheet
L5  环境     夜色调 / 窗光 / 雨 / 阴影圆          叠加层
──── 以下【不进美术】──────────────────────────────
L6  标注     名字 / 价格 / 来源 / 褪色 / 选中环
L7  面板     四角 HUD + 详情页
```

> ★★ **L6 / L7 一律不进 canvas、不交给美术。**
> 理由不是省事，是**它们在表达"这条信息有多旧"** —— 那是代码里的规则（`tintOf` / 褪色 class），
> 必须一条规则改一处。美术化了以后，改一次衰减曲线要重画一套图。

**标注的视觉 = 纸片**：
```
名字/价格 → 一张半透明纸片贴在建筑或人头上
  background: #f7f4ee / 88% 不透明 · 圆角 3px · 1px 描边 #ded7c8 · 无阴影
  褪色      → 纸片整体 opacity 0.9 / 0.72 / 0.55 / 0.4（按情报年龄 4 档）
  不认识的人 → 不给纸片（地图上没名字）
```
这就是 `ui-design.md` 里"情报旧了会褪色"落到画面上唯一的样子。

## 四、资产清单（Demo 范围）

一个场景 + 15 人。**先做这一批，够跑通 demo 验收四条。**

```
地面   草地 ×1（可平铺 32×32）· 泥土 ×1 · 广场砖 ×1 · 水 ×1 · 过渡角 ×4
道路   直 · 弯 · 十字 · T · 尽头 ×（沥青面 + 人行道边 + 标线）= 5 种 ×1
装饰   树 ×3（大中小）· 灌木 ×2 · 长椅 · 路灯 · 垃圾桶 · 邮筒 · 停着的车 ×3 · 花坛
建筑   小店 ×2 · 住宅 ×3 · 加工厂 ×1 · 市场 ×1 · 广场设施 ×1   ← 每种 1~2 变体
       ★ 每栋交付: 屋顶面 + 立面揭示 + 门口（位置单独给 JSON）
实体   人: 4 向 × 走 4 帧 × 站 1 帧 = 20 帧/人 —— 但 15 人【共用基础体型】
       靠 §六 的"显著特征"区分，不靠 15 套全身图
环境   阴影圆 · 选中环 · 雨（可程序生成）· 窗光遮罩 · 夜间色调
```

**招牌文字不进贴图** —— 招牌底是美术，**字是代码画的**。
原因：编辑器能改建筑名，贴图带字就写死了。（美术只交"一块空招牌底"。）

## 五、建筑交付规格

```
尺寸      w 格 × 32 px  ×  h 格 × 32 px   （例: 6×4 格 = 192×128 @1x, 384×256 @2x）
锚点      左上角对齐格子左上角
图层      一张 PNG: 屋顶 + 立面揭示 + 阴影（阴影另给一张透明的更好，方便夜/雨复用）
门口      JSON: { "doors": [ { "side":"south", "offset":0.5 } ] }  ← 逻辑要用（走路终点）
招牌位    JSON: { "sign": { "x":8, "y":6, "w":80, "h":14 } }       ← 代码在上面画字
可选      每个建筑 2 个变体（换屋顶色 / 换窗户排布）→ 一条街不重复
```

## 六、15 个人的「可辨识性」规格 ★

契约写着 **可区分性 > 随机性**。所以不是"随机生成 15 张脸"，而是**在有限维度上取互不相同的组合**：

| 维度 | 取值 |
|---|---|
| 身体 | 高瘦 / 中等 / 矮胖 |
| 头发 | 短发 / 长发 / 白发 / 帽子 |
| 上衣色 | 4 色（从城市色板里取，别用 UI 强调色） |
| 配饰 | 眼镜 / 围裙 / 拐杖 / 包 / 无 |
| 职业道具 | 无 / 工牌 / 菜篮 / 工具 |

**要求**：任意两人**至少 3 个维度不同**。（契约 §三 的验收）

> 这一条比画得好看重要得多 —— **玩家要一眼认出"那是王阿姨"**，
> 而这正是整个游戏的验收标准①「我认得他们」。

## 七、时间与天气（美术要提前留量）

HUD 上有 `时间 · 天气 · 温度`，所以画面必须跟着变。**这层比想象中占工作量。**

```
白天/黄昏/夜晚   → 一层全屏色调（multiply）+ 窗光层（夜晚才亮）
                    ★ 不需要三套素材，一套 + 两层叠加就够
雨              → 一层条纹/粒子 + 地面反光（可选）
晴/多云/阴       → 云的移动阴影（可选，后面再说）
温度            → 不改画面（只在 HUD 显示）
```

**建议**：先把**夜间色调 + 窗光**做出来（性价比最高，一眼就有"城市活起来"的感觉），
雨和多云往后放。

## 八、交付契约（美术怎么把图放进来）

```
assets/
  ground/   grass.png  dirt.png  plaza.png  water.png
  road/     straight.png  curve.png  cross.png  t.png  end.png
  props/    tree_s.png tree_m.png tree_l.png bush_1.png bush_2.png ...
  bld/      shop_a.png shop_b.png home_a.png home_b.png home_c.png
            factory.png market.png plaza.png
            shop_a.json   ← 门 / 招牌位
  people/   base_a.png base_b.png base_c.png        ← 3 种体型
            hair_short.png hair_long.png hair_white.png hat.png
            top_1..4.png  acc_glasses.png ...
  fx/       shadow.png  ring.png
```

命名规则：`小写_下划线`，尺寸写进同目录 `index.json`（美术不用记代码）。
**代码侧只认文件名**，所以美术可以在不改一行代码的情况下替换任何一张。

在原型里对应的一行（占位 → 真素材）：
```js
// 现在（代码画的占位）
d.style.background = `linear-gradient(...)`;
// 换成素材
d.style.backgroundImage = `url(assets/bld/${kind}_${variant}.png)`;
```

## 十、待定（要拍）

```
① 夜里"人"要不要打手电/有轮廓光？   ← 影响夜间可读性
② 建筑要不要"内部可见"（俯视看到地板）还是只看到屋顶？  ← 决定家具怎么画
   （现在是只看到屋顶；但"屋子里长什么样"是交互的一部分）
③ 车要不要会动（马路上跑）？  ← 会显著增加工作量
④ 季节 / 天气长期变化要不要做
```
