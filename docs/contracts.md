## 〇、先厘清三层（否则表会互相污染）

```
真值（事实层）  这条记忆里到底有什么        → 由感知/传闻写入
精度档          这条记忆还剩多清楚          → 决定【说什么】(槽位填什么)   ← 表 1.2
性格与心情      这个人怎么把它说出口        → 决定【怎么说】(片段怎么选)  ← 表 1.3 / 1.4
```

**两条纪律**：

1. **精度改"说什么"，性格改"怎么说"——两者不许互相影响。** 刻薄的人说"五块"也是五块。
2. **表达层不许造新信息**（决定 B4/B7）。渲染只能填槽位、只能选片段，**不能引入真值里没有的实体或数字**。

## 一、模板池表达维度表

### 1.1 现状（已实现，别推翻）

`game/lines.py` 现在是 **7 个 act × 组合式模板池（opener + core + tail）**，选段靠
`_pick(speaker, act, topic, salt)`（crc32，确定性、不掷骰子、带"第几天"轮换）。

> 2026-09 分层修正：**说什么是 `npc/semantic.py`（结构化事件 + 真值），怎么说才是
> `game/lines.py`**。价格在事件里是**数字**，到渲染才变成 "8块" —— 这样
> 「精度衰减」才有东西可衰减。

```
ACTS = STATE · INTENT · SURPRISE · DOUBT · DENIED · REPORT
PRIORITY = DOUBT(6) > DENIED(5) > SURPRISE(4) > INTENT(3) > STATE(2) > REPORT(1)
```

**本表不换机制，只加一层"过滤"**：

```
候选片段池 = POOL[act][seg]  ∩ 【persona 允许集】∩【mood 允许集】
选中       = _pick(...) 不变   ← 不引入任何新随机
```

### 1.2 精度档（决定"说什么"）★ 核心新增

按 `remember` 分桶（决定 B3）。**数值与非数值走不同的渲染规则。**

| 档 | remember | 数值类（价 · 量 · 时长） | 非数值类（地点 · 人 · 事件） |
|---|---|---|---|
| 5 精确 | ≥ 0.9 | `4块5` | `王阿姨住街对面，周三来买梨` |
| 4 一位 | ≥ 0.7 | `4块多` | `王阿姨常来买梨` |
| 3 区间 | ≥ 0.5 | `不到5块` / `5块上下` | `有个常来的阿姨` |
| 2 方向 | ≥ 0.3 | `比别家便宜` | `那家店有人气` |
| 1 印象 | ≥ 0.1 | `那家不贵` | `那家还行` |
| 0 忘 | < 0.1 | **不产生信息**（不是"说不知道"，是这行已经没了） | 同左 |

**硬规矩（决定 B4）**：档位只会**向下降**。"4块5" 可以变 "4块多"，**绝不能变 "5块2"**。
`_fill` 已有的行为（缺槽位就整段去掉、绝不留下 `{item}`）就是这条规矩的现状实现 —— **保持它**。

### 1.3 persona 维度（静态 · **造人器的输出维度** · 决定 B9）

> ⚠ **造人器只允许在这 7 个维度上编人。** 编不出来的维度 = 模板池说不出的性格 = 游戏里不存在。

| # | 维度 | 枚举值 | 表达效果（过滤哪些片段） | 行为效果（落到哪个参数） | 现状 |
|---|---|---|---|---|---|
| P1 | **话量** | 闷 / 常 / 话痨 | 闷：opener 只留 `""`；话痨：opener 全留 + tail 留带拖音的 | `tell_bias` 0.3 / 1.0 / 2.0 | ✅ `tell_bias` 已有 |
| P2 | **态度** | 乐观 / 中性 / 刻薄 | tail 收尾倾向：乐观留`"！"`类、刻薄留`"……"`类 | 纯表达（不落参数） | 🆕 |
| P3 | **直白度** | 直说 / 拐弯 | 直说：opener 只留 `""`；拐弯：opener 留缓冲词（`嗯……`） | 纯表达 | 🆕 |
| P4 | **好奇** | 爱打听 / 无所谓 | REPORT/DOUBT 是否主动开口（允许集） | 闲逛倾向（`fun` 驱动） | ⚠ 部分（`fun` 有，挂钩无） |
| P5 | **对钱** | 抠门 / 一般 / 大方 | 提到价钱的频率与口气 | `personality["thrift"]` 0.6 / 1.0 / 1.5 | ✅ `thrift` 已有 |
| P6 | **礼貌** | 客套 / 生硬 | 称谓与语气助词（`哎` / `啧`） | 纯表达 | 🆕 |
| P7 | **口味偏重** | 重吃 / 重睡 / 重玩 / 平衡 | STATE/INTENT 里哪个 need 更常出现 | `personality[signal]` 1.3 / 0.8 | ✅ 已有 |

**组合数**：3×3×2×2×3×2×4 = **864 种人**（远比 40 人多 → 不会撞脸）。

### 1.4 mood 维度（动态 · 短期 · 不进造人器）

| # | 维度 | 来源 | 表达效果 |
|---|---|---|---|
| M1 | **身体** | `signals`（hunger/energy/bladder） | STATE 的 core 选哪个 need |
| M2 | **情绪** | `fun` + 最近成功/失败 | 临时覆盖 P2（乐观的人也会烦） |
| M3 | **对听者的亲近** | 同 `home` / `favor` | 是否用 P6 的客套集 |
| M4 | **相信度** | `believe` | 选 DOUBT 还是 REPORT |

### 1.5 选段规则（给软工，照这个实现）

```python
允许(act, seg) = 片段.允许集 ∩ persona(act,seg) ∩ mood(act,seg)
子池 = POOL[act][seg] ∩ 允许(act,seg)
若 len(子池) < 2: 子池 = POOL[act][seg]          # 兜底：绝不许把话说没
pick = _pick(speaker, act, topic, _SALT[seg])     # 不变
```

### 1.6 扩张纪律

```
加一个 act 或一个片段 → 随便加，只要不新增实体/数字
加一个 persona 维度   → 必须同时改造人器（否则是"没有人有的性格"）
维度超过 8 个          → 停下来问：这个性格真的会被玩家观察到吗？
```

## 二、数据源清单

> **决定 A2**：面板上每个字段都必须回答"发行版玩家从哪儿合法知道它"。
> **答不出的字段不许上界面。**

### 2.1 六个合法来源

| 代号 | 来源 | 精度 | 带来源与时间？ |
|---|---|---|---|
| **A** | **我自己经手**（账本） | **精确** | ✅ 精确到 tick |
| **B** | **我亲眼看见**（当场、视野内） | 精确 | 只在当场；事后靠记忆衰减 |
| **C** | **我打听来的** | 按 `remember` 分档 | ✅ `source` + `last_seen` |
| **D** | **传闻传到我耳朵里** | 更模糊 | ✅ 但 `source` 可能是 `unknown` |
| **E** | **雇人替我看**（买别人的时间） | 同 C（**有损二手**） | ✅ 来源 = 雇员 |
| **F** | 🚫 **不可得（红线）** | — | — |

**F 的内容（谁都不能给）**：
```
· 别人此刻脑子里确切的内容（只能问出来，且是他【愿意说】的版本）
· 世界的真值：别家的真实库存 / 真实售价（除非我亲眼看 / 听人说）
· 对手的账、对手的利润、对手的定价逻辑
· 全城客流统计 · 市场份额 · 声誉分 · 排名
· 别人之间说了什么（除非传到我这儿）
```

### 2.2 现状 `snapshot.py` 字段 → 发行版合法性

| 现状字段 | 谁知道 | 发行版 | 处置 |
|---|---|---|---|
| `npcs[].money` | 自己 | **F**（对别人） | 发行版**只给自己**；别人只能靠外表/传闻猜 |
| `npcs[].signals` | 自己 | **F**（对别人） | 发行版只给自己；别人的需求只能看**行为**（activity） |
| `npcs[].memory` | 自己 | **F**（对别人） | ★ 发行版**永不下发**；打听走**渲染后的回答**，不是原始行 |
| `npcs[].intent` | — | **F** | 调试器专用（玩家只能看**行为**，不能看**打算**） |
| `npcs[].events` | 双方 | **C/D** 部分 | 只有**与我相关**或**我听到**的才合法 |
| `npcs[].plan` | 自己/雇员 | **F**（对别人） | 别人的日程不可见 |
| `npcs[].favor` | — | **C/D**（印象级） | 只能问出来，且是对方的**表达**，不是原始数 |
| `economy.companies[].cash` | 自己公司 | **F**（别家） | ★ 对手的账**永远不可得**（决定 Q12-B） |
| `economy.counters / on_duty` | 自己店 | **F**（别家） | 别家有几个工位在岗 → 只能**去看**或**听说** |
| `entities[].price` | 我家货架 | **B**（别家） | 别家的价 → 必须走到门口看，或打听 |
| `entities[].stock` | 我家 | **B/C**（别家） | 同上 |
| `activity_log` | 自己 | **B**（别人） | 只有我**看见过**的那段才合法 |
| `companies[].staff` | 我自己雇的 | **部分** | 我雇的人我全知道；别家的人只知道"见过谁在那站台" |

**推论（给软工）**：
```
snapshot 要裂成两个出口：
  dev 出口   = 现状（全量，给上帝版/测试）
  play 出口  = 只含 A/B/C/D/E 的字段，且【别人的 memory/intent/favor/cash 一律不出门】
             + 一份【账本】块（A 类，精确）
             + 一份【我听说过/我问过】块（C/D/E 类，带 source 与 tick）
```

### 2.3 三条硬规矩

```
① 别人的 memory 永不直接下发 —— 打听返回的是【渲染后的一句话 + 来源 + 时间】
② 对手的钱、别人的意图、全城统计 —— 三样永远不给（F）
③ 每个 play 出口字段，必须在【本表】里能找到一行。找不到 → 不许加。
```
