> 2026-09-18 · 架构访谈（30 问）的净结果。**本文是设计真源。**
> 与 [游戏构思](game-concept.md) / [Demo 计划](demo-plan.md) / [现状与拍板](checklist.md) 冲突时**以本文为准**（冲突已回写原文）。
> 认知总结与团队分工见 [架构师简报](architect-brief.md)。

## 一、总纲

> **一个视野有限的人，在一座小城里靠关系和情报做买卖；他靠别人记得他活着，最后要么穷死，要么自己走了。**

```
没有输赢 · 没有胜利宣告 · 没有失败画面
死亡真实存在，唯一死法 = 缺钱饿死
唯一的"完成" = 系统在你够格时把门打开，走不走由你
```

**一条主链**：`声誉 → 钱 → 食物 → 活着`

## 二、决定清单

### A · 玩家的认知（有限视野怎么落地）

| # | 决定 | 为什么 |
|---|---|---|
| A1 | **两个构建**：上帝版（点谁看穿谁，测试用）/ 发行版（看不了）。**同一套 UI，只换数据源。** | Demo 要能验证机制；发行要保住有限视野 |
| A2 | **数据源纪律（硬）**：面板上每个字段都必须回答"发行版玩家从哪儿合法知道它"。答不出的字段不许上界面 | 这是有限视野的**唯一可逐字段检查的守卫** |
| A3 | **交易落账，对话不落账**。账本 = 人名册 + 讣告：谁 · 何时 · 买了什么 · 多少钱 · 第几次来 · 上次来是几天前 | 交易是客观事实（店主本来就记账）；对话出了门就只在你脑子里 |
| A4 | **手机落账，当面不落账**（手机后期做） | 当面 = 有温度没记录；手机 = 有记录没温度 |
| A5 | **状态读数 = 从账本 + 记忆推导的"我的城"**。自己经手 = 精确；别人头脑里 = 模糊。**没有声誉分 / 客流统计 / 市场份额** | 替代品是一份人名册 + 时间 |
| A6 | 账本是全城唯一客观记录，也是玩家的**验尸报告**（死亡必须可复盘） | 没有输赢，就必须让玩家事后能知道"我哪一步错了" |

### B · 信息与传播

| # | 决定 | 为什么 |
|---|---|---|
| B1 | **打听 = 免费 + 费时间**；**买情报 = 删除**（不能花钱买信息）。信息只能自己探索、洞察 | 钱买不到真相 |
| B2 | 钱能**雇人替你看**（买别人的时间），但拿到的仍是**有损的二手观察**，不是数据 / 报告 / 真值 | 成长有出口，但有限视野不破 |
| B3 | **精度衰减按 `remember` 分桶**：≥0.9 精确值 · ≥0.7 一位精度 · ≥0.5 半开区间 · ≥0.3 定性方向 · ≥0.1 整体印象 · <0.1 忘掉 | 一个旋钮同时管"传得越远越模糊"和"放得越久越模糊" |
| B4 | **红线：衰减只允许丢精度，不允许造新信息**（"四块五"→"四块多" ✓；→"五块二" ✗） | 否则"自然产生"会变成"随机编造" |
| B5 | **评价可以凝固成事实**（`origin: self → hearsay → unknown`）—— 这就是声誉的传播方式 | 靠的不是事实校验，是"信的人多不多" |
| B6 | **亲身经历永远压过传闻**。传闻只锁得住"从没亲自来过的人"；翻盘唯一的路是让他们亲自来 | 否则玩家会被一条凝固的谣言永久锁死 |
| B7 | **表达层只允许改评价（valence），永远不准改内容（content）** | 同一句"苹果五块"：可以说"挺便宜"或"也就那样"，但**五块还是五块** |
| B8 | **台词全走规则模板池**（persona × mood × 精度档），**不接 LLM** | 确定性、零成本、可快进；恢复 checklist §1 #11 的原决定 |
| B9 | **模板池的表达维度 = 造人器生成性格的输出维度**，两者必须是同一个集合 | 否则生成出来的性格在游戏里"说不出来"= 不存在 |

### C · 店与经济

| # | 决定 | 为什么 |
|---|---|---|
| C1 | **店 = 一组工位**；产能 = 在岗工位数；**玩家能占一个工位打工** | 店不是"开/关"，是"几个工位在岗" |
| C2 | **0 人在岗 = 0 产出** | 复用工位模型；"你在不在"代价最直接、最可见 |
| C3 | 雇人 = **买工位 + 招人 + 付工资**（买时间） | §五"钱买时间"的具体账 |
| C4 | **钱只能买两样：时间 / 生产资料（工位、机器）**。声誉和信息钱一样都买不到 | 三条线不可互兑，唯一兑换物是时间 |
| C5 | **雇人的副作用**：站在那个工位上挣到的脸面，是雇员的，不是你的 | 买到了时间，买不到脸面 |
| C6 | **定价需要市场洞察**（定价 = 你掌握的情报的直接兑现） | 给了"情报"一直缺的那个用途 |
| C7 | **行业竞争是真主菜**，不是背景 | 对手是城里唯一会持续、主动、不可逆地夺走东西的人 |
| C8 | **死亡 = 缺钱饿死**（破产不直接结束，它让你慢慢饿死） | 和内核零成本对齐（`hp` 本来就只由 `hunger` 参与） |
| C9 | **生理自动保留**（有食物自动吃），**但没有任何救助** | 防"忘记吃饭"，不防"没有饭吃" |
| C10 | 外部市场**无限供货 + 收购产出**，闭环在城外 → **瓶颈是钱流，不是物资** | 调参目标 = 就业与工资分配，不是物资生产 |

### D · 对手与 LLM

| # | 决定 | 为什么 |
|---|---|---|
| D1 | **对手老板 = 和玩家受同样约束的对称 agent**（只读自己的记忆决策） | 赢在信息质量，不是赢在数值；内核天然支持 |
| D2 | **一条"经营决策"接口，两个驱动**：AI 老板（自动）/ 玩家面板（手动） | 玩家可无头测试；难度靠参数不靠剧本 |
| D3 | **LLM 藏在接口后面**，内核不依赖 LLM | 离网 / 快进 / 测试 / 回放 一样不丢 |
| D4 | 规则驱动 = 确定性 · 默认 · 无头 · 快进 · 离线 · 平衡测试；**LLM 驱动 = 在线 · 人味 · 每局不同** | 两全 |
| D5 | **LLM 每次决策落盘成 transcript** → 同 seed + 同 transcript = 可完整回放 | 把确定性救回来 |
| D6 | **LLM 只看老板的记忆**；输出必须过 **schema 校验**才能变成世界命令 | 红线在结构上守住，不靠 prompt 自觉 |
| D7 | **快进区间降级到规则驱动**；LLM 只在玩家视野内触发 | "快进 = 跳到" 才不会被 API 往返卡死 |
| D8 | 更甜版本：LLM 出**性格与偏好**，规则出**可校验命令** | 人味归 LLM，物理归引擎 |

### E · 一局 / 生死 / 造人

| # | 决定 | 为什么 |
|---|---|---|
| E1 | **一局无期限**（高自由度沙盒，不掐表） | 不掐表 → 你要自己定目标 |
| E2 | **造人器**：结构（住哪 / 岗位 / 作息 / 关系骨架）程序生成；人味（名字 / 性格 / 口气 / 怪癖）LLM 生成**一次**后**冻结成数据** | **每局的人不同 + 整局完全确定** 同时成立 |
| E3 | **一局 = 固定地图骨架 + 全新的人 / 关系 / 性格 / 初始记忆** | 地图你熟，人你不熟 → 上一局的经验不可照抄 |
| E4 | **生成器三约束**：可区分性 > 随机性（每人至少一个独有记忆点）· 关系网稀疏 + 聚类 + **桥接人** · 关系从接触点长出来 | 15 张脸要认得出来；人人互相认识则传闻 1 跳传遍全城，信息差不成立 |
| E5 | **生成器输出形状 = 场景数据字段形状**（Demo 手写 15 人也要照填） | 否则正式版接生成器要返工 |
| E6 | **人口只减不增**（不做新增人口，架构留"接收"口） | 城的衰减变成叙事，而不是内容刷新 |
| E7 | **人只能死，不能搬走** → **玩家是这座城里唯一能离开的人** | 与 tagline"去看更大的世界"对称，且不需要新系统 |
| E8 | **每一次减员，账本必须让玩家有可能发现** | 否则减员只是背景噪音；快进会让你整段错过（§七#14 的代价） |
| E9 | **§七#4"世界演化" = 熟人改行**（关店 / 改行 / 开第二家 / 去打工），**删掉"新居民搬来"** | 人口只减不增下，只有"你认识的那个人变了"才成立 |
| E10 | **离场：够格时开门，玩家自选离开**。系统不宣布赢，只让"离开"这个选项出现 | "够"只有玩家能定义；结束是唯一一个由你亲手做出的重大决定 |

### F · 开局

| # | 决定 | 为什么 |
|---|---|---|
| F1 | **外来者开局**：你新搬来，城里人彼此认识，你是外人 | 天然解释有限视野 + 初始怀疑 + 打听的起点 |
| F2 | 物质：一个工位 · 很少库存 · 够买几天货但**不安全**的现金 | 第一幕：你就是这家店 |
| F3 | 社会：**一个种子关系**（房东 / 远亲 / 老同学）——你全城唯一认识的人 | 他是你第一次"打听"的对象 |
| F4 | 认知：你只知道自己的店在哪 + 那个人告诉你的几句话 | — |
| F5 | 对手：**隔壁已经有一家本地人开的店** | 压力从第一天就在，理由也天然 |

## 三、被推翻的原文

| 位置 | 原文 | 处置 | 理由 |
|---|---|---|---|
| `game-concept` §一 | "声誉游戏——**钱是记分牌，不是玩法**" | **改**：没有输赢，钱不是记分牌；**钱是命**（缺钱饿死） | E1 / C8 / E10 |
| `game-concept` §五 | "钱只能买**三样**：时间 / 信息 / 脸面"；"买信息：电脑 / 雇人跑腿" | **改成两样**：时间 / 生产资料。**电脑买情报删除**；雇人只能买"别人的时间"（有损二手观察）。**脸面买不到** | C4 / B1 / B2 |
| `game-concept` §六 | "点开任何一个人，能看到他记得什么、从谁那儿听来的" | **改**：仅上帝版；发行版只读账本 + 记忆 | A1 / A5 |
| `game-concept` §七#1 | "爽点在**声誉**（不是数字做大）" | **改**：声誉是**引擎**，不是目标；目标由玩家自定 | E1 / E10 |
| `game-concept` §七#4 | "世界会自己演化（对手开店 / 楼空 / **新居民搬来**）" | **删"新居民搬来"**，改**"熟人改行"** | E6 / E9 |
| `game-concept` §七#13 | "快进 = 跳到，不是快放" | **加条件**：快进区间走**规则驱动**，LLM 只在玩家视野内触发 | D7 |
| `game-concept` §七#15 | "**不让你死**，但也不替你做任何有意义的决定" | **撤销前半句**：死亡真实存在，唯一死法 = 缺钱饿死。后半句保留 | C8 / C9 |
| `game-concept` §八 | "✗ 城市经营：玩家不修路 · 不盖楼 · 不规划地块" | **放宽**：工位 / 雇人 / 排班 / 竞争都在，但玩家不被强制微操 | C1–C3 / D1 |
| `game-concept` §九 | 与 Big Ambitions 对比："我们不去挤【经营手感 + 内容量】那一头" | **需重写**：我们也有对手老板 AI 了，那条不再是分界线 | D1 / D2 |
| `checklist` §1 #11 | "语义层上层：只做语域（persona × mood），不接 LLM" | **保留**（本文恢复了它） | B8 |
| `checklist` §1 #13 | "生老病死：只保留饿死 / **累死**" | **改**：只剩**饿死**（引擎本来就只支持饿死） | C8 |
| `checklist` §3 | "明确不做：…… / **LLM 润色** / ……" | **改**：LLM 只用在**对手老板的经营决策**，不用在台词润色 | D3 / B8 |
| `demo-plan` §四 | "✗ 手机（当面搭话已经证明了同一条通道）" | **保留**，但登记为已知风险：发行版的"过时"要等手机才第一次被验证 | A4 / A2 |

## 五、已知风险与悬案

| # | 风险 / 悬案 | 状态 |
|---|---|---|
| 1 | **经营决策接口横跨 `npc/` 与 `world/` 的边界**（公司账在世界侧，记忆在认知侧） | **未解决**：必须设计成窄口，否则会为省事破坏"决策只读记忆" |
| 2 | **表达维度 ≠ 生成维度** → 生成出来的性格说不出来 | 未解决：先定 ⑧ |
| 3 | **Demo 只在上帝版验证"过时"** → 发行版可读性无人验证 | 已接受（手机是唯一解药） |
| 4 | **就业 / 工资**是全城最重要的两颗数值旋钮 | 待长局跑回来（README"60 天全灭"的根因） |
| 5 | **只有 1 个程序** → 排期串行 | 已接受；靠"别的线产出不依赖代码的东西"缓解 |
| 6 | **人口只减不增** → 每局轨迹单调衰减 | 已接受（外部市场闭环，饿不死）；靠 ⑦ 把衰减变成叙事 |
| 7 | **玩家"够格"的判定条件**（E10 那扇门的门槛） | 未定：需要一组可从账本推出的条件 |
