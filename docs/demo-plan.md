# Demo 计划

配套文档：[游戏构思](game-concept.md)

---

## 一、Demo 只证明一件事

> ## "顾客是人" —— 你能感觉到"王阿姨这个人"。

不是"游戏完整" ✗。**验收四条**，全中才算成功：

```
① 我【认得】他们   有名字 · 有习惯 · 我一眼知道"他今天来没来"
② 他们【记得】我   我涨价降价后，能看到"谁知道了、谁知道的是旧价"
③ 他们【会传话】   我能看见"谁跟谁说了什么"，也能听见
④ 我能【打听】     点人搭话，答案来自他的记忆（可能过时、可能是听来的）
```

---

## 二、Demo 范围

```
地图   1 个小场景（复用 config/scenes/scene.json）：你的小店 + 几户人家 + 广场
NPC    10~15 人（不是 40 —— Demo 只要能认得出来）
商品   3~5 种（苹果 / 梨 / 简餐 …）
公司   你的店（玩家 = 老板）
时长   3~5 个游戏日就能看出"人记得你"
```

---

## 三、要做的模块（分三组）

### A · 让玩家能玩

| 模块 | 做什么 | 验收 |
|---|---|---|
| **A1 玩家化身** | 把 `decide()` 的输入从打分器换成点击；点击映射到端口动词 | 能走 · 能拿 · 能买 · 能用 |
| **A2 走过去 + 房间内锚点** | NPC / 玩家在房间里有坐标；"走到某个点"（去柜台 / 去货架 / 去找人）| 不再"隔空取物 / 隔空交易" |
| **A3 快进到 X** | 条件快进（有人进店 / 到某点 / 有人说话）+ 结束摘要 | 一天不用真等 24 分钟 |

### B · 让"人"被看见 ★ 核心

| 模块 | 做什么 | 验收 |
|---|---|---|
| **B1 看穿一个人** | 点人 → 他的需求 · 记忆（含来源）· 今天干了什么 | 一眼能回答"他为什么不来" |
| **B2 看见传播** | 气泡 + "谁跟谁说"的连线；只画**与你有关的** | 能看见一条消息在扩散，且不刷屏 |
| **B3 打听（搭话）** | 问 → 他从记忆里答，带"亲眼 / 听说"标注；问多了会烦 | 同一个问题，不同人 / 不同天答案不同 |

### C · 让信息能沉淀

| 模块 | 做什么 | 验收 |
|---|---|---|
| **C1 玩家的笔记本** | 听到的价 / 事记下来（带来源和日期）| 能对比"我记得的"和"实际" |

---

## 四、构建顺序（每步都能单独验收）

```
0. 契约落成代码（见第六节）      ← 只有这步做完, 其余人才能并行
1. A1 + A2   能在场景里走 / 拿 / 买 / 用（不隔空）
2. B1        点人看穿他          ← ★ 到这儿就能"感觉到人"了: 核心验证点
3. B3        搭话、答案来自记忆
4. B2        看见传播（只画与你有关的）
5. A3        快进到 X + 摘要      ← 能玩得下去
6. C1        笔记本
```

**先不做**（不是不重要，是 Demo 用不上）：

```
✗ 手机（当面搭话已经证明了同一条通道）
✗ 家具买卖 / 房租 / 买房（先用"食物"就够）
✗ 外面世界 / 终局目标 / 雇人打探
```

## 五、五条开发线

| 线 | 碰哪里 | 交付 |
|---|---|---|
| **1 UI / 信息设计** | `godot/scripts/ui/**` | 经营界面 · 看穿一个人 · 笔记本 · 快进控件 |
| **2 玩家控制** | `godot/scripts/render`（点击）+ `state/` + 玩家化那条路 | 点击→动词 · 走过去 · 不隔空 |
| **3 传播模型** | `npc/semantic.py` · `npc/memory.py` · `world/run/gossip.py` | 值得说 · **精度衰减失真** · 问答接口 |
| **4 契约 / 数据桥** ★ | `gateway/snapshot.py` · `gateway/server.py` | 记忆/来源/传播事件发出去 · 玩家意图收进来 |
| **5 内容 / 场景** | `config/**` + 编辑器 | 小场景 · 15 个人的名字性格习惯 · 3~5 种货 |

**依赖关系**：`4` 先做 ✓ → 然后 `1 / 2 / 3 / 5` 可并行 ✓（`3` 可无头测试，最独立；`5` 不依赖代码，可最早开工）

## 六、契约（先定这个）

> 它是线 1 / 2 / 3 的**唯一接缝**。没定它，三条线互相等；定错了，就是"前端看不到数据"。

### 6.1 读一个 NPC（看穿一个人）

```
{
  "id": "npc_wang_ayi",
  "name": "王阿姨",
  "home": "bld_008",
  "loc": "bld_004",                    // 此刻在哪
  "activity": ["eat", "苹果"],          // 此刻在干什么
  "signals": {"hunger": 0.42, "energy": 0.7, "bladder": 0.9, "fun": 0.6},
  "money": 138,
  "favor": {"bld_004": 1.4},            // 对我这家店的好感
  "on_post": false,
  "memory": [                            // ★ 他记得什么 —— 含来源与确信度
    {"item_id": "food_apple_048", "afford": "hunger", "value": 0.35,
     "price": 5.0, "located": "bld_004",
     "remember": 0.62,                   // 记得多清楚(会衰减)
     "believe": 0.95,                    // 有多信
     "source": "",                       // ""=亲眼 · "npc_li_si"=听谁说的
     "last_seen": 30240}
  ],
  "today": [                             // 今天干过什么(时间线)
    {"at": 512, "kind": "eat", "target": "food_apple_048"},
    {"at": 540, "kind": "told", "target": "npc_li_si", "about": "food_apple_048"}
  ]
}
```

### 6.2 问一个 NPC（搭话）

```
请求:  {"ask": "price", "about": "food_apple_048"}     // 问: 你觉得这个多少钱
       {"ask": "about", "target": "bld_014"}            // 问: 你觉得对面那家怎么样
       {"ask": "gossip"}                                // 闲聊: 最近有什么新鲜事

回答:  {
  "ok": true,
  "topic": "food_apple_048",
  "text": "苹果啊？我上礼拜看是五块",      // 人话(由记忆渲染)
  "from_memory": {"price": 5.0, "remember": 0.62,
                  "source": "", "when": 30240},          // ★ 依据
  "origin": "self" | "hearsay" | "unknown",              // ★ 亲眼 / 听说 / 忘了谁说的
  "mood": "willing" | "reluctant" | "annoyed",           // 愿不愿意说(取决于好感)
  "favor_delta": -0.02                                   // 问多了会烦
}
```

**两条设计约束**：

```
① 回答【只能来自他的记忆】—— 引擎里没有的, 他答不出 ✓（这保证"人是人"）
② 回答一定带【来源】：亲眼 / 听说 / 忘了谁说的 ✓
   → 玩家因此能校准"该信多少" ✓ 而且来源链会断 ✓（引擎的 source 字段已有）
```

## 七、分工（5 人）

> **硬事实：只有 1 个程序 ✗ → 排期必然串行 ✓**
> 所以分工的关键是：**让另外 4 个人产出的东西尽量不依赖代码** ✓
> （好消息：这游戏最难的几件事恰好都不用写代码）

| 人 | 现在就能开工 | 交付物 | 什么样算完成 | 不该做 |
|---|---|---|---|---|
| **架构师** ★杠杆最高 | 纸上三件 | ① **契约**（第六节）② **参数表**（记忆半衰 · 信任折扣 · **精度衰减** · 保质期 · 保本工资 · 好感回升，每条附"为什么"）③ **模块边界**（哪个文件归哪条线）| 程序照着能直接写、不用再问 | 不要自己抢程序写代码 |
| **UI 设计** ★最该先做 | 线框图 | ① 点开一个人看到什么 ② 经营主界面 ③ 笔记本 ④ 快进控件 + **一份"什么该给玩家看 / 藏"的说明** | 能回答"玩家为什么看不见全貌" | 先别做美化（风格未定）|
| **美术** | 2D 俯视素材 | 12 种建筑俯视图 + 地面/道路 + 15 个小人；**顺手给这 15 个人起名 + 定长相** | 先"占位但风格定下来"（代码不需要美术也能跑）| 别做等距 / 3D（已定 2D）|
| **测试** ★形态特殊 | 验收清单 | ① **长局可信度**：跑 N×30 天回答"这世界说得通吗"（`sim_report` 现成）② **契约测试清单**（每个字段都在）③ 每条流的"算完成"标准 | 能说出"这次改动让世界变得可信 / 不可信" | 不要只点按钮找 bug |
| **软件工程师** ★关键路径 | 契约 → 地基 | ① 把契约落成代码 → **解锁所有人** ② 再做 **A1 + A2** | 场景里点一下能走 / 买 / 用 | 不做内容 · 不做美术替换 · 不做界面美化 |

**有一个人没被安排到 ——「造人」**（15 个 NPC 的性格 / 作息 / 关系），建议拆两半：

```
美术   给名字 + 长相（反正要画 15 张脸，顺手）
架构师 填性格 / 作息 / 熟人关系 / 初始记忆（这是"设计参数与关系"，和架构师同构）
→ 这块【完全不依赖代码】✓ 且贡献七成"人味" ✓ 应该最早开工
```

**也没人专职管数值** —— Demo 阶段由 **架构师定 + 测试用长局跑回来** ✓ 循环起来就够（专职数值是以后的事）。

## 八、难点提醒（传播系统，线 3）

真正难的是这四处，别低估：

```
① "值得说"的判据   什么都说 → 噪音 ✗；只说重要的 → 像剧本 ✗
② 失真 ★           不要"随机改数字"✗，要【精度逐级衰减】✓✓
                     亲眼 "四块五" → 二手 "四块多" → 三手 "不到五块"
                     → 四手 "挺便宜的" → 五手 "那家还不错"
                     不用随机数 ✓ 自然产生 ✓ 玩家一眼看懂"传了几手" ✓✓
③ 可观察性         全画出来 → 满屏气泡 ✗ → 只画【与你有关的】
④ 玩家插进传播链   你说了话会不会被传 ✗ 传成什么样 ✗
                     → 这就是"你的声誉是怎么长出来的" ✓ 说错话也会被传 ✓
```
