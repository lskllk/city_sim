## 1. 定位（一句话）

**玩家是一个可自由行动的 NPC（店主），在一座"活着的城市"里开店。** 不是上帝视角。

```
支柱 A  顾客是【真实 NPC】: 有需求 / 日程 / 记忆 / 信任。
        禁止抽象出"客流量 / 平均满意度"当玩法输入 —— 那是把 NPC 退化成统计。
支柱 B  气泡 = 语义层可视化: NPC 说了什么，就是它内部真的发生了什么。
        气泡撒谎 = 游戏撒谎。由真实状态长出，不是装饰。
```

### 1.1 铁律（违反就当场崩，优先于一切机制）

| # | 铁律 | 含义 |
|---|---|---|
| **P8** | **玩家的手只能碰世界，碰不到 NPC 的脑子** | 经营动作只写世界真值（改价 → 世界立刻变，**但没人知道**）。NPC 的知识**只能**由 **感知**（`perceive_into`）或 **传闻**（`_notify_due`）写入。禁止任何"全局同步 NPC 知识"的捷径 |
| **R1** | **数据里不出现「时刻 → 行为」的映射** | "夜里困得快"合法；"22:00 睡觉"是编排 |
| **R2** | **惩罚 = 状态调制产出**（不做门禁） | 阈值只放在**得分**上；不做"违规扣分"。穷 → 买不起 → 更穷，是同一个环 |
| **R3** | **随机只在措辞层** | 语义层（谁 / 知道什么 / 什么强度 / 什么行为）必须是真的、确定的 |
| **R4** | `npc/` **不 import `world`** | 层隔离（`tests/test_import_layers.py` 强制） |
| **R5** | **看不见 ≠ 没发生** | 玩家只经营一家店，视野外照常演化 —— 这是"玩家影响整座城市"的来源 |
| **R6** | Godot **只渲染 / 发命令**，不计算 simulation | 前端所有"看起来聪明"的东西都是后端给的 |

### 1.2 具身化管理

全局管理能力由**特殊物件**提供：**电脑**（与它交互 → 经营面板：招聘 / 定价 / 管理）。
→ **还没做**（见 checklist「未实现」）。

## 2. 内核机制（已实现；参数在 `config/sim.toml`）

### 2.1 决策：效用主导

```
eff = (need^power × 净收益 × personality × believe) / (1 + λ × cost)
净收益 = value − (该需求每 tick 掉的量 × 走的 tick × 走路放大系数) ÷ 买几份   ← 任何信号通用
cost   = price×qty + price × (1 − believe)           ← 纯钱 + 不确定性
```

| 参数 | 现取值 | 意思 / 改它会怎样 |
|---|---|---|
| `utility.threshold` | `0.05` | **唯一阈值**（在得分上）。同时承担"琐碎需求别动"与"别为小事跑一趟" |
| `utility.power` | `3.0` | 需求急迫度幂次。> 1 放大真缺口 |
| `utility.power_by_signal` | `energy = 4.0` | 每种需求可以更"钝"（不太困就别去躺） |
| `utility.cost_lambda` | `0.02` | 成本权重 λ，越大越抠（只管钱与不确定性） |
| `utility.travel_penalty` | `2.0` | 走路放大系数（1.0 = 纯物理）。**想"更怕走路"就调它** → 近店优先 |
| `utility.preempt_ratio` | `1.5` | 迟滞：新的比当前**好这么多倍**才改主意（1.0 = 抽风） |
| `utility.plan_pull` | `0.15` | 计划（承诺）的基础拉力；需求超过 `plan_pull × preempt_ratio` 才能顶掉日程 |

- **路费按买几份摊**：只买 1 个 → 这趟消耗全压在它身上 → **近店好**；
  一趟囤 N 份 → 摊到 N 份上 → **远店不再是劣势**。（买得多本来就该少跑几趟）
- **候选不过滤**：记忆里的行全部参与打分（删掉了 `REFLEX_SIGNALS` 白名单与 `fallback_need`）。
- **单轨**：`_goal` 一个，`source ∈ {need, plan}`；`Person.decide` = 需求 > 日程 > idle。
- **异地成本 = 路上需求的消耗**（净收益里扣）；`move_penalty`/`time_value` 都已删。

### 2.2 需求（`[metabolism]` + `[energy_rhythm]`）

| 信号 | 速率 | 含义 |
|---|---|---|
| `hunger` | `-1/720` | **半天**从满到空 |
| `energy` | `-0.5/1440` | **两天的基准**；真正放倒人的是夜里那一段倍率 |
| `bladder` | `-1/2304` | ≈1.6 天；另有三餐的跳量（`add_pending bladder_pending`） |

```
energy 消耗 = 基准 × 昼夜倍率 × 活动倍率
  [energy_rhythm]: 白天 1.0 · 19:10 起 3.0 · 21:00 陡增到 9.0 保持到 23:00
  [activity] busy_energy_mul = 1.8（交互/赶路；睡觉【冻结】）
  → 傍晚还剩 ~0.6，两个小时被榨干 → 自己爬上床（数据里没有"到点睡觉"）
```

**睡觉必须回血**：`bed_basic.json` 的 `on_complete: add_signal energy +1.0`。
（不回血 = 睡醒还是 0.3，作息永远立不起来 —— 踩过。）

### 2.3 生命 `hp` 三态（`[health]`）

```
hp ↓    hunger == 0  或  energy == 0
hp ↑    hunger ≥ hp_regen_floor(0.5)  且  energy ≥ 0.5
其他    不动（中间带 —— 否则咬一口饭 hp 就开始涨，"饿死"永远发生不了）
hp < hp_override(0.5) → 日程失去拉力（命比钱大）。bladder 不参与 hp。
```

### 2.4 知识与记忆（`npc/memory.py`）

- 一行记忆 = `MemItem`：`located / owner / afford / value / price / stock / tags / shelf_life_ticks`
  + **`believe`**（我信几分）+ **`remember`**（我还记不记得，半衰期 `knowledge.half_life_ticks = 2880`）
  + **`source`**（`""` = 亲眼所见 / `npc_id` = 他说的 / `ad:<bid>` = 广告）。
- **`stock == -1` = 不知道 / 无限**，**`stock == 0` 才是"空"**（空的不值得跑一趟）。
- **新建记忆行默认 `believe = 1.0`（亲眼）**。`believe = 0` 会让这一行永远不可能被选中 —— 踩过。
- 写入口只有两个：**感知** `perceive_into`（亲眼 → `believe = 1.0`）、**传闻** `_notify_due`（听来 → 打折）。

### 2.5 买卖与囤货

```
成交: 扣钱 → 减店库存 → 送货【进家】的同类容器(合并 stock; 保质期取最早到期)
        → 买家记忆写一行(believe=1.0)
囤货: 目标存量 = 每天消耗份数 × 保质期天数 × stock_fill(0.8) × thrift
      —— "在它坏掉之前我吃得完多少"。短保的自然囤得少。只对 tags 含 consumable 生效。
      (床/马桶的 stock 恒为 1，对它算目标存量会推出"囤 2.5 张床" —— 踩过)
变质: EntityDef.shelf_life_ticks → Expires_tick 到点 stock=0 + spoiled 事件;
      非 persist_empty 的直接销毁并清记忆。
```

**没做**：卖家**收不到钱**（`_execute_buy` 只有 `npc.pay(cost)`，钱凭空消失）。
→ 这是「经济闭环」缺失，也是"大家饿死"的根本原因。

### 2.6 传播（`world/engine.py::_notify_due`）

**一对一搭桥**，每 tick 每地点：

```
① 我这一轮想不想开口        tell_p(0.3) × tell_bias
② 愿不愿意【跟这个人】说    tell_same_home(1.0) / tell_stranger(0.15)
③ 对方愿不愿意停下来听      listen_p(1.0)
→ 只搭【一条桥】; 说的人这轮不再听、听的人这轮不再说(说的不听/听的不说)
→ 先收集所有过闸的人, 再【按权重抽一个】(不能按 id 顺序取第一个 —— 同屋会永远排前面)
```

**六条硬规则** `_may_tell`：① 对方已知不说（天然衰减器，所以不需要 hops 计数器）
② 别把"他刚告诉我的"再告诉他（认 `source`）③ 别告诉他他家东西 ④ 自家东西不是新闻
⑤ 自己不太信的（`believe < 0.3`）不传 ⑥ 话题冷却 240 tick（对不同人也算）。

```
trust_between(): 同 home(同一层) 0.9~1.0 | 其他 0.4~0.7 —— 按两人 id 用 crc32 派生
                 (零存储、可回放，不用内置 hash() —— 它每进程随机化)
听者记忆 believe = 说话人的 believe × trust；source = 说话人 id
```

### 2.7 语义层（`npc/semantic.py`）

```
act: STATE / INTENT / SURPRISE / DOUBT / DENIED / REPORT
     优先级 DOUBT > DENIED > SURPRISE > INTENT > STATE > REPORT
触发: 感知时"预期 vs 观察"落差 → SURPRISE; 那条记忆本来是别人说的 → DOUBT(可溯源)
      开始新需求动作 → INTENT; 行动失败(钱不够/没货/被占) → DENIED
句子: 组合式模板池(opener+core+tail), 选哪段由 speaker/act/topic/天 确定性派生
      —— 不掷骰子也不重复; 槽位只允许真值
气泡: 后端决定文字 → 快照 bubble{text,until,kind} → 前端只画; 只在【关注范围】冒
```

### 2.13 批发市场 + 开零售的前提

```
市场 config/market.json: 固定商品 / 数量无限 / 【只有公司能采购】/ 价格是进货价(低于零售价)
   → market.purchase(公司, 店, 品类, 份数): 公司账 −价 × 份数, 货上架到那家店的货架
   → market.restock_all(): 每天开门那一刻, 各公司把货架补到 restock_to 份(简单经营规则)
   → 空货架 persist_empty=true, 卖空了也留着等下次进货
开零售的前提(用户拍板): 【店铺建筑必须登记公司才能卖】—— 没登记 → 成交被拒
   ("这家店没有登记公司"), 也给编辑器一个能看见的错误
```

### 2.12 经济：公司（最小闭环）

```
数据: config/companies.json  [{id: org_<kind>_<slug>, name, cash, owner,
                               shops:[建筑 id], staff:[{npc, wage}]}]
      → 装配时把归属写进 location["company"]（成交时一句话查到公司）
钱的两条腿:
  ① 成交: 买家付钱 → 记进【店铺所属公司】的账（双分录；以前这钱凭空消失）
  ② 工资: 每天 wage_minute(480=08:00) 公司给店员发薪, 钱从公司账出 → 员工个人
         现金不足 → 发事件 wage_failed, 那个人这天就没收入(没有"欠薪"概念)
观测: hello.companies(账/老板/员工) + 事件 wage_paid/wage_failed + 地点页显示公司现金
```

> **为什么是公司**：用户拍板"经济做成公司的单位" —— 店铺属于公司、公司有账、
> 工资从公司出；老板以后就是玩家化身，经营面板在这个账上做加减。
> **没登记公司的店**：货款仍然"消失"（旧行为），把"店主=公司"留到经营面板那一步。

### 2.8 推送（观察驱动）

```
60Hz 恒定; 只推「渲染状态变了的 NPC ∪ 观察集(focus_npc/focus_loc)」
位置只在【状态迁移】时推(途中一帧不推, 客户端按 travel 折线插值)
状态未变 → 不推; 超时 → 丢帧不断线; HUD 显示 ↓/↑ 字节/秒
客户端时钟: 连续调速(rate = tps × clamp(1+err×K)) —— 不用硬 cap,
            硬 cap 会让时钟卡在服务端整数 tick 上 = 走一步停一步(踩过)
服务端时间基准: 用【真实经过的 dt】累加 tick, 不用标称 interval(否则 1x 只跑 0.5 tick/s)
```

### 2.9 空间与楼层

```
建筑 floors: N → 导出 bld_007 本体 + bld_007_f1..fN(同 footprint + part_of)
容量 = 单层容量 × 层数(占地不变 = 密度↑不是铺开)
每层是一个【家】→ home 的高信任分组按【楼层】分开, 不是整栋楼
编辑器: kind=home 才收住户(办公楼 capacity=200 是工位, 不是床位 —— 踩过)
```

### 2.10 命名（`docs/naming.md`，`tests/test_naming.py` 强制）

```
id:    地点 <slug>_<NNN>(+_fN)  实体 <itemtype>_<NNN>  NPC npc_<姓拼音>_<名拼音>
展示名: 与编号解耦 —— 作者没起名 → 「类型名 + 同类型序号」号(小屋1号);
        起了名字 → 用作者的(王二家)。展示名不进 id。
```

## 3. 编辑器 / 观察器

- **编辑器**（作者态，不跑 simulation）：画路 → 放建筑 → 楼层/住户/物件/认知(批量)/
  **按人注入记忆**/导入导出场景 JSON。工具：填满住户、清理无效引用、重排重复建筑名、
  **无住所的人面板**（分配空床位 / 全部删除）。
- **观察器**（只读）：只订阅 gateway 的 `/ws`，`Store` 是只读镜像；
  地图标签按 LOD 分级（名称 0.62 / 角标 0.85 / 徽记 1.05 / 明细 1.15）；
  Event Log 显示"决策/完成/失败/购买/转述/变质/被拒"。

## 4. 明确不做（重要的简化，别再讨论）

| 不做 | 理由 |
|---|---|
| `F2` 自由块 | utility 主导后多余 |
| `REFLEX_SIGNALS` + 双轨仲裁 | 计划只是偏置 → 没有"要抢占的计划" |
| `home_bias` 归巢兜底 | NPC 有需求自然会回家 |
| `safety` 安全感、`alertness` 拆信号 | 单信号 `energy` 够用 |
| 多 `afford` 物品 | 等真需要"一个物品满足两种需求"再做 |
| 时/刻 → 行为的映射 | 违反 R1 |
| "客流量 / 平均满意度"聚合层 | 违反支柱 A |
| **招牌(门口广播)** | 已删: 它是"经营手段", 归公司侧; 现在整条链(数据/后端/前端/编辑器)已移除 |
| 全局同步 NPC 知识 | 违反 P8 |
| **verify 校验闭环**（到店发现不符 → 源可信度下降） | 已拍板不做 → P6"骗"玩法整条线放弃 |
| **情绪 / 关系网 / trust 演化** | 已拍板不做 |
| **Episode（L1 情景记忆）** | 已拍板不做 —— L0 物化记忆够用 |
| **衰老 / 生育**（人口演化） | 已拍板不做 —— 只保留饿死 / 累死 |
| **LLM 润色（语义层 M-S3）** | 已拍板不做 —— 只做语域(persona × mood) |
| **编辑器编 `plans` / `pulses`** | 已拍板不做，也不手改 JSON —— **游戏内部写死规则** |
| **视口过滤 / 静态段按需推** | 已拍板先不做（实测带宽够用） |
| `nn/` 学习层 | 占位，不在路线图里 |
