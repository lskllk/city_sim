# 游戏设计 · 一页

> **一个视野有限的人，在一座小城里，靠关系和情报做买卖；赚够了钱，去看更大的世界。**

底子是 `citysim`（确定性城市模拟内核）。它不是"带聪明 NPC 的经营游戏" ✗
而是**声誉游戏** —— 钱是记分牌，不是玩法 ✓

---

## 一、四条格局

| # | | 说明 |
|---|---|---|
| 1 | **小店起步** | 一家小超市（品类少），**柜台交易** —— 每次买卖都是一次"人和人见面" ✓ |
| 2 | **玩家的视野也是有限的** | 和 NPC 一样：知道自己家、知道路，只看到"那边有个建筑"；不知道别的店卖什么、房子里有什么 |
| 3 | **小城 + 一条通往外面的路** | 外面不是"另一张地图"，而是**货源 / 商品 / 信息的来源**；挣够了钱可以去看 |
| 4 | **手机** | 有联系方式才能聊；顾客觉得你不错会加你 → **通讯录 = 你的情报网** |

---

## 二、已定的设计决定（附"为什么"）

| # | 决定 | 为什么 |
|---|---|---|
| 1 | **类型 = 店主经营，爽点在声誉**（不是数字做大）| 内核唯一做得出来的是"人记得你" |
| 2 | **规模 = 小镇 ~40 人**（常客 15~30）| 声誉要"认得出来"；上限是你能记住多少张脸 |
| 3 | **地图 = 固定骨架**（玩家改不了）| "王阿姨每天路过你的店"靠的是稳定的空间关系 |
| 4 | **世界会自己演化**（对手开店/楼空/新居民）| 把"可变"从"玩家是上帝"变成"世界在演化，你在其中" |
| 5 | **画面 = 2D 俯视** | 沉浸感来自"看穿一个人"，不来自镜头；2D↔2.5D 只是换投影层，可逆 |
| 6 | **玩家 = 一个有腿的 NPC** | 能出门、能搭话、需求会掉；点击映射到已有的端口动词 |
| 7 | **柜台交易**（不做自助）| 人和人见面才有记忆/好感/传闻 |
| 8 | **玩家的记忆不衰减，但世界会变** | 让玩家体验"过时" ✓，不让他体验"遗忘" ✗ |
| 9 | **传播分三层** | 事实（记忆行）· 传播（谁→谁）· 表达（一句话）—— 玩家是传播层里的一个节点 |
| 10 | **空间：逻辑用"同 region"，表现用锚点** | "谁跟谁能说话"= 同一地点（已有）；"看起来在对话"= 锚点 + 走到某点 + 靠拢/连线 |
| 11 | **核心循环 = 分配你的一天** | 干活 / 出门 / 维护关系 / 活着 —— 四件事互相抢时间 |
| 12 | **钱只能买"时间、信息、脸面"** | 不能买装饰、不能买车买房；否则后期就是无底洞 |
| 13 | **快进 = 跳到，不是快放** | 引擎确定性 + 可无头跑 → 后台算到底再给你看（快放会撞 CPU 墙）|
| 14 | **快进有代价** | 你的需求也在掉；**世界在变而你没看见** ← 紧张感的来源 |
| 15 | **自动边界**：生理自动（吃/上厕所），**决策一律不自动** | 不让你死，但也不替你做任何有意义的决定 |

## 三、明确不做（反范围）

```
✗ 生活模拟：不买车 · 不买房自住 · 不逛街买衣服 · 不做装修审美
✗ 城市经营：玩家不修路 · 不盖楼 · 不规划地块
✗ 对话树 / 写死台词（会盖掉 NPC 真实的记忆）
✗ 战斗 / 技能树 / 数值成长
✗ 多人联机

✓ 玩家在城里的"生活"只有两件事: ① 他的店   ② 他在城里的脸面
```

---

## 四、核心循环

```
你一天 1440 tick, 花在四件事上:
  ① 干活      收银 · 补货 · 装修 · 记账
  ② 出门      去看 / 去听 / 去打听
  ③ 维护关系  搭话 · 请客 · 回手机
  ④ 活着      吃饭 · 睡觉

钱不能直接替你做事 ✗ 它只能: 买时间（雇人）· 买信息（电脑/跑腿）· 买脸面（请客）
→ 所以"花钱"和"分配时间"是同一件事的两面 ✓
```

**紧张感的三个来源**：

```
① 我不知道全貌（视野有限 ✓）
② 我没时间全看（四件事抢时间 ✓）
③ 我看到的可能是旧的（世界在变，记忆会过时 ✓）
```

---

## 五、Demo 要证明的一件事

> **"顾客是人"—— 你能感觉到"王阿姨这个人"。**

不是"游戏完整" ✗。只要这四条成立，Demo 就算成功：

```
① 我【认得】他们     有名字 · 有习惯 · 我一眼知道"他今天来没来"
② 他们【记得】我     我涨价降价后，能看到"谁知道了、谁知道的是旧价"
③ 他们【会传话】     我能看见"谁跟谁说了什么"，也能听见
④ 我能【打听】       点人搭话，答案来自他的记忆（可能过时、可能是听来的）
```

---

## 六、Demo 的范围

```
地图  1 个小场景（复用 config/scenes/scene.json）：你的小店 + 几户人家 + 广场
NPC   10~15 人（不是 40 —— Demo 只要能认得出来）
商品  3~5 种（苹果 / 梨 / 简餐 …）
公司  你的店（玩家 = 老板）
时间  3~5 个游戏日就能看出"人记得你"
```

## 七、要做的模块（分三组）

### A. 让玩家能玩

| 模块 | 做什么 | 验收 |
|---|---|---|
| **A1 玩家化身** | 把 `decide()` 的输入从打分器换成点击；点击映射到端口动词 | 能走、能拿、能买、能用 |
| **A2 走过去 + 房间内锚点** | NPC/玩家在房间里有坐标；"走到某个点"（去柜台 / 去货架 / 去找人）| 不再"隔空取物/隔空交易" |
| **A3 快进到 X** | 条件快进（有人进店 / 到某点 / 有人说话）+ 结束摘要 | 一天不用真等 24 分钟 |

### B. 让"人"被看见 ★核心

| 模块 | 做什么 | 验收 |
|---|---|---|
| **B1 看穿一个人** | 点人 → 他的需求 · 记忆（含来源）· 今天干了什么 | 一眼能回答"他为什么不来" |
| **B2 看见传播** | 气泡 + "谁跟谁说"的连线 | 能看见一条消息在扩散 |
| **B3 打听（搭话）** | 问 → 他从记忆里答，带"亲眼/听说"标注；问多了会烦 | 同一个问题，不同人/不同天答案不同 |

### C. 让信息能沉淀

| 模块 | 做什么 | 验收 |
|---|---|---|
| **C1 玩家的笔记本** | 听到的价/事记下来（带来源和日期）| 玩家能对比"我记得的"和"实际" |

---

## 八、构建顺序（每一步都能单独验收）

```
1. A1 + A2   能在场景里走、拿、买、用（不隔空）
2. B1        点人看穿他            ← 到这儿就能"感觉到人"了 ✓✓ 核心验证点
3. B3        搭话、答案来自记忆
4. B2        看见传播
5. A3        快进到 X + 摘要        ← 能玩得下去
6. C1        笔记本
```

**先不做**（不是不重要，是 Demo 用不上）：

```
✗ 手机（当面搭话已经证明了同一条通道 ✓）
✗ 家具买卖 / 房租 / 买房（先用"食物"就够 ✓）
✗ 外面世界 / 终局 / 雇人打探
```

## 九、引擎给我们的（不用新写）

```
✓ 世界 · 经济 · NPC 认知 · 记忆衰减 · 传闻 · 好感度 · 囤货
✓ 柜台交易 · 进货 · 定价 · 雇人 · 排班 · 工资 · 生产(加工厂)
✓ 时间控制 pause/1x/10x/100x/1000x ✓ 确定性可复现 ✓
✓ 编辑器（做场景）· 事件流 · 时间线 · 点人查看的 inspector
✓ 端口动词 try_move / try_take / try_buy / Interact / observe
```

**要小心的**：`npc/` 不得 import `world/`（层隔离）✓ 玩家接进来时别破这条 ✓
