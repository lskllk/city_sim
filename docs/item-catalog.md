# 物品设计（Item Catalog）

> **这份文档定义"这个游戏卖什么、买什么、用什么"，不定义数值平衡（数值在 `config/`）。**
> 上游：[资产定义](asset-list.md)（物件的分类判据）· [游戏构思](game-concept.md)（玩法）
> 现状：`config/items/*.json` 只有 9 件 —— 本文是扩到 **65 件**的提案。

## 〇、先立一条判据

> **物品的差异必须落在【钱 × 时间 × 保质期】三个轴上。**
> 不落在三轴上的新物品，就是"换个名字的同一个东西"，加了也不增加玩法。

| 轴 | 两端 | 它制造什么取舍 |
|---|---|---|
| **钱** | 便宜 ↔ 贵 | 定价、囤货、客群分层 |
| **时间** | **即食** ↔ **生食**（要加工） | 省钱但费时间 —— 而时间是这个游戏最硬的资源 |
| **保质期** | 长（可囤） ↔ 短（会烂） | 进货节奏、损耗、现金流压力 |

三个轴的极端组合就是有趣的物品：

```
即食 + 贵 + 极短   →  热菜        （最好吃，但今天不卖掉就烂）
生食 + 便宜 + 极长 →  米          （最划算，但要花时间做）
即食 + 便宜 + 极长 →  泡面        （穷人救星；代价是 fun−）
贵 + 无保质期      →  礼品        （钱换成关系）
不满足任何需求     →  日用品      （但每天都得买 —— 客流引擎）
```

## 三、需求与信号的映射

内核只有 5 个信号：`hunger` `energy` `bladder` `hp` `fun`。

| 信号 | 由什么满足 |
|---|---|
| `hunger` | ①②③ 主食/生鲜/即食 |
| `energy` | ⑤ 咖啡/茶 · ⑩ 床 |
| `bladder` | ⑩ 马桶 |
| `fun` | ④ 零食 · ⑤ 汽水/啤酒 · ⑦ 娱乐 |
| `hp` | 只有饥饿参与（不打药） |

**推论**：
```
· 食物是"刚需" → 保证有人来，但大家都会卖 → 拼价格
· fun 是"选择" → 只有你有的东西，才能定高价
· 日用品不满足任何信号 → 它需要【另一个购买动机】(见 §六)
```

## 四、价格带与毛利结构

```
廉价带  ¥1~3    米/面/白菜/矿泉水/日用品       走量 · 薄利 · 保证客流
中档带  ¥3~6    苹果/梨/面包/牛奶/简餐/零食     主力 · 毛利中
高档带  ¥6~12   便当/热菜/咖啡/风筝/玩具        毛利高 · 但客群窄
礼品带  ¥10~30  花束/点心盒/水果篮/酒           钱换关系 · 不走量
原料带  ¥1.6~4  工厂产出 · 只能出口             城里的外部现金来源
```

**店主的真正决策**：
```
① 我进哪几类？        只卖吃的（客流窄）vs 加上日用品（每天都有人）
② 我囤什么？          耐放的（米/泡面）vs 易腐高毛利的（热菜/牛奶）
③ 我靠什么赚钱？      走量（水/盐）vs 高毛利（热菜/礼品）
④ 我要不要买冰柜？    加投资 → 敢进易腐货 → 打开高毛利那条线
⑤ 我要不要摆灶台？    把米变成简餐 → 但要占一个人的时间
```

## 五、谁买什么（需要新机制）

现在内核只有 `personality[signal]`（重吃/重睡/重玩）—— 只区分"多饿"。
要让商品线真正变宽，需要**偏好标签**：

```
甜 / 咸 / 清淡 / 酒 / 烟 / 便宜 / 讲究 / 新鲜
```

然后 NPC 有各自的偏好权重，于是：

```
王阿姨   讲究 · 新鲜    → 买水果、买当天简餐
李大爷   清淡 · 便宜    → 买米、买白菜、买茶
周师傅   咸 · 便宜      → 买泡面、买馒头、买啤酒
年轻人   甜 · 讲究      → 买零食、汽水、便当
```

**这一条把"卖什么"变成"卖给谁"** —— 是这类游戏最有价值的纵深。
⚠ 但它是新机制，要内核加字段。

## 七、砍到最小：先做这 12 件

如果一次做不完，**这 12 件就能撑起"三类客群 + 三条策略"**：

```
主食   米 · 面包                       ← 便宜/耐久 vs 即食/会烂
生鲜   苹果 · 牛奶                     ← 便宜耐放 vs 贵易腐（逼出冰柜需求）
即食   简餐 · 热菜                     ← 主力毛利 vs 高毛利高损耗
零食   饼干                            ← fun 这条线
饮品   汽水 · 咖啡                     ← fun vs energy
原料   简餐原料                        ← 出口闭环
家具   货架（容器）· 冰柜 · 灶台         ← 三件改经济参数的家具
```

**这 12 件之外先不做。** 每加一件，都要能说出它落在"钱/时间/保质期"哪个轴上。

## 八、和资产的关系

物品定下来之后，资产侧（[asset-list](asset-list.md) §D）每件要出三张：

```
itm_goods_<id>_full      世界形态（俯视）+ 存量刻度条
itm_goods_<id>_empty     空态 = "卖光了"
ui_icon_<id>             图标（正视 16×16）
```

**65 件 × 3 = 195 个资产文件** —— 但生成器一条命令的事。
不过**图标可以偷懒**：同一类（比如 7 件日用品）可以共用形状、只换颜色和细节。
