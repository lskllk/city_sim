# 游戏 UI 与信息设计

> 角色：UI / 信息设计。**只谈玩法与信息，不设计接口**（那 是线 4）。
> 上游真源：[设计决定](decisions.md) · [契约](contracts.md)（数据源纪律 A–F / 精度档）· [游戏构思](game-concept.md) · [Demo 计划](demo-plan.md)
> 凡与真源冲突，以真源为准。本文只做**落地**。

---

## 〇、一句话

> **这个游戏的 UI 不是仪表盘，是一本可能过时的笔记本。**

仪表盘显示"现在是多少"。笔记本显示"我什么时候、从谁那儿、听说了多少"。
**前者会杀死这个游戏** —— 因为有实时真值的地方，就没有"信息差"，而没有信息差，这个游戏什么都不剩。

所以整个信息设计只有一个中心任务：

> ## 让玩家**感觉到**「我知道的是旧的」。

下面每一条都是这条的推论。

---

## 一、五条设计原则（从玩法推导，不是审美）

| # | 原则 | 从哪来 | 落到 UI 上 |
|---|---|---|---|
| **P1** | **没有实时数值** | 数据源纪律 F | 每个数字都必须带**来源 + 时间**；带不上的数字不许上界面 |
| **P2** | **时间是一等公民** | 决定 #8（玩家记忆不衰减，世界会变） | 时间不是角落里的时间戳，是**主要视觉维度**（越旧越褪色） |
| **P3** | **我记的是记录，不是真相** | 决定 #18（精度只降不升） | 笔记本**永不自动刷新**；只能靠"去看 / 去问"更新 |
| **P4** | **钱是命，不是分** | 决定 #20（唯一死法是缺钱饿死） | 显示**今天净变化**和**发薪倒计时**，不显示"总收入" |
| **P5** | **人是主角，数字是配角** | 决定 #2（40 人，你要认得出来） | 认出"王阿姨"优先于任何聚合数字；聚合统计一律 F |
| **P6** | **能用世界表达的，不用文字** ★ | 这游戏不是文字游戏 | 优先级：世界表现 > 图形/形状 > 图标 > 数字 > 文字。**文字是最后手段** |

### ★ P6 的落地：每一条信息都先问"世界能不能直接演出来"

| 信息 | ✗ 文字做法 | ✓ 世界做法 |
|---|---|---|
| 我没去过这家店 | `？ 还没去过` | **建筑是铅笔草稿**（虚线轮廓、没上色），名字也不给 |
| 我记的价旧了 | `6 天前` | **建筑泛黄褪色** |
| 这个价我有多确定 | `不到5块` / `4块多` | **一条刻度上的区间条**：精准=一个点，模糊=一段越来越宽的带 |
| 他是听说的 | `<span>打听</span>` | **引号形状 + 淡描边**（亲眼 = 实心锐利；传闻 = 虚线 + 涟漪） |
| 他饿了 | `activity: "来我店里"` | **头顶徽章 + 姿态**（捂肚子、拖着走） |
| 这人是熟客 | `见过 11 次` | **进门直接走向柜台**；生人**在门口犹豫一下**（带 `?`） |
| 我的声誉 | 声誉分 78 | **谁在门口犹豫、谁直接进门**；账本里"上次来几天前" |
| 时间在走 | 只有时钟 | **昼夜色调 + 窗光**（已在做） |

**判据**：如果一个信息**只能**靠读字得到，它多半是设计还没做完。

## 二、基础原子：一条「情报」

这个游戏里**所有**可显示的事实都是同一个东西，反复出现：

```
        内容        来源        时间         精度          确信
         ¥5.0       亲眼(B)     2 天前       清晰(5)        很高
```

**来源**用 [契约 §2.1](contracts.md) 的六个代号：

| 代号 | 来源 | 表里怎么画 |
|---|---|---|
| **A** | 我自己经手（账本） | 实心 · 精确 · 可按 tick 回溯 |
| **B** | 我亲眼看见 | 实心 · 精确 · **只在当场精确，事后靠记忆** |
| **C** | 我打听来的 | **带引号** · 精度降档 · 标注说话人 |
| **D** | 传闻传到我耳朵 | 带引号 · 更低档 · 来源可能是"不知道谁说的" |
| **E** | 雇人替我看 | 同 C，但标注**雇员的名字**（有损二手） |
| **F** | 🚫 不可得 | **不画。连"？"都不给。** |

### ★ 一条必须写死的纪律：「？」只能表示"可得但还没得"

```
没去过的店      →  「？」   ← 这是钩子（B 类，走过去就有）
别人的口袋有多少钱 →  不画     ← 这是 F，画"？"会变成永远打不开的门
```

**混淆这两者会毁掉玩家的时间感** —— 他会以为每个"？"都能被解开。

### 精度档的视觉词典（数值类）

按 [契约 §1.2](contracts.md)，档位只降不升。UI 上要一眼看出档位：

| 档 | 显示 | 视觉 |
|---|---|---|
| 5 精确 | `¥4.5` | 正文色 |
| 4 一位 | `4 块多` | 正文色 |
| 3 区间 | `不到 5 块` | 略淡 |
| 2 方向 | `比别家便宜` | 淡 + 斜体 |
| 1 印象 | `那家不贵` | 很淡 |
| 0 忘 | **不产生信息** | **这行已经不存在了**（不是"说不知道"） |

> **"她说 4 块多"和"她说 5 块 2"是两种东西。** 前者是传播，后者是发明。UI 不许把发明画得像传播。

## 三、三个尺度

玩家一天里在这三个尺度之间来回跳。**每个尺度都有自己的一套"我知道什么"。**

```
   城（我在哪 · 能去哪）        ── 骨架全知道, 内容才知道
        ↕
   人（我认识谁 · 他怎么想）      ── 只有【关系】, 没有【属性】
        ↕
   我（店 · 钱 · 身体 · 一天）   ── 唯一能【精确】的地方
```

## 四、屏幕清单

### 4.1 主界面（地图 + HUD）

```
┌──────────────────────────────────────────────────────────────┐
│ 第 3 天  14:20      [⏸][1x][10x][100x]     [笔记本] [账本]     │
│ ¥412   ▼今天 -38                                              │
│ 饥 ▓▓▓▓░░  精 ▓▓▓░░░  憋 ▓▓░░░░                              │
├──────────────────────────────────────────────────────────────┤
│                                                              │
│        ╔═══════════╗                                         │
│        ║ 吵吵小店   ║      ← 我的店(高亮, 我在里面)           │
│        ║ 苹果 5.0  ║                                         │
│        ║ 简餐 8.0  ║                                         │
│        ╚═══════════╝                                         │
│                                  ┌────────────┐              │
│                                  │ 街角水果铺  │              │
│                                  │   ？        │ ← 没去过     │
│                                  └────────────┘              │
│                                                              │
│      🧍 王阿姨 ← 认识(名字)                                   │
│      🧍 某居民 ← 不认识(不显示名字)                           │
│                                                              │
└──────────────────────────────────────────────────────────────┘
```

**HUD 刻意只有三样**：时间（+快进）· 钱（+今天净变化）· 我自己的三个需求。

| 元素 | 来源 | 为什么 |
|---|---|---|
| 时间 / 快进 | — | 时间是玩法（决定 #11） |
| 钱 | **A**（我自己的账） | P4：显示**今天净变化**，让人看到在流血 |
| 饥/精/憋 | **A**（我自己的身体） | 只有自己（对别人是 F） |
| 建筑骨架（路/轮廓/门/招牌名） | 常识 | 决定 #3：地图骨架固定，你熟 |
| 建筑内容（卖什么/多少钱） | **B/C/D** | ★ 核心：没去过就不知道 |
| 人的名字 | 账本（见过几次） | ★ 声誉可视化：**不认识的人没有名字** |
| 人的行为（在干什么） | **B**（只有我看到的） | 需求是 F，只能从行为推 |

**红线**：
- ✗ 不放声誉分 / 排名 / 市场份额 / 客流统计 —— 全 F
- ✗ 不放"我店里现在几个人" —— 我不在场就不知道（在场才知道）
- ✗ 别人的钱、需求、意图 —— F

### 4.2 我的店（经营面板）

四个 Tab。**经营动词与命令集一一对应**（架构师要求）。

```
┌─ 我的店 ─────────────────────────────────────────────────────┐
│ [ 货架 ]  [ 账 ]  [ 人 ]  [ 今天 ]                            │
├──────────────────────────────────────────────────────────────┤
│                                                              │
│ 货架                                        我上次改: 今早   │
│   苹果     ¥5.0    剩 12 份     [ 改价 ] [ 补货 ]            │
│   简餐     ¥8.0    剩  2 份  ⚠  [ 改价 ] [ 补货 ]            │
│   ────────────────────────────────────────────────           │
│   柜台 1 人: 李四(在岗)                                      │
│                                                              │
└──────────────────────────────────────────────────────────────┘
```

**「账」Tab**（P4 的落点）：

```
│ 现金        ¥412                                            │
│ 今天        收 +68   支 -106（进货 -80 / 工资 -26）           │
│ 下次发薪    第 8 天 08:00    还差 ¥112   ⚠ 按现在速度不够     │
│                                                              │
│ 按天（近 7 天）  ▁▂▅▇▆▁▁   ← 只画【我自己】的收支, 别人的永远没有│
```

**「今天」Tab** ★ 声誉玩法的核心：

```
│ 今天（第 3 天）                                              │
│   ◉ 我去店里站柜台                                           │
│   ○ 让 李四 顶班                                             │
│                                                              │
│ 本周我在店里        一 二 三 四 五 六 日                      │
│                     我 我  ·  ·  ·  ·  ·                     │
│ 上周                我 我 我  ·  ·  ·  ·                     │
│                                                              │
│ ⚠ 老顾客记得的是【站柜台那个人的脸】。                        │
│   你已经 2 天没露面了。                                      │
│   → 上周挣到的脸面, 记在李四头上。                            │
```

> ★ **这是本设计最有信心的一格。** 决定里写着"雇人的副作用：站在那个工位上挣到的脸面，是雇员的，不是你的"—— 但**如果不显示，玩家永远学不会**。把它做成可见的、有历史的、会累积的东西，"花钱买时间"和"丢脸面"才成为同一个决定的两面（决定 #12）。

### 4.3 关系页（点一个人）

**发行版点人打开的是「关系页」，不是「属性页」。** 因为别人的 memory / signals / intent / money 全是 F。

```
┌─ 王阿姨 ────────────────── 见过 11 次 · 上次 3 天前 ──────────┐
│                                                              │
│ 现在   在 吵吵小店 买东西          ← B（我看见的）            │
│                                                              │
│ 我记得她                                                     │
│   每周三来买梨                     ← C（她说的/我总结的）      │
│                                                              │
│ ─────────────────────────────────────────────────           │
│  [ 问价 ]   [ 问那家店 ]   [ 闲聊 ]     ← 三个动词 = 命令集   │
│ ─────────────────────────────────────────────────           │
│ 我以前问过她                                                 │
│   09-15  苹果 ¥5.0                             ← C          │
│          她说: "街上都这个价"                                │
│          ↳ 她也只是听说                        ← ★ 传了几手   │
│   09-11  梨  ¥3.5  亲眼                  ← B                │
│                                                              │
└──────────────────────────────────────────────────────────────┘
```

**这个页面里没有的东西（全是 F，一个都不许有）**：
```
✗ 她想要什么（hunger/energy）    → 只能从她的行为看
✗ 她有多少钱                     → 只能从外表/传闻猜
✗ 她记得什么（原始记忆行）        → 只能【问】，拿到的还是她愿意说的版本
✗ 她对我的好感数值                → 只能从"愿不愿意答"感觉出来
✗ 她接下来打算干什么              → 只能看
```

> **demo-plan B1 的"一眼看穿他"是上帝版面板**（开发/验证用），见 §七。发行版就是上面这个。

### 4.4 打听

回答必须带**依据**（demo-plan §6.2 已定）。UI 的任务是让"该信多少"一眼可读。

```
        ┌─────────────────────────────────────────────┐
        │  王阿姨 说：                                 │
        │                                             │
        │     "苹果啊？我上礼拜看是五块"               │
        │                                             │
        │  ── 依据 ─────────────────────────────      │
        │  来源   亲眼（她看到的）                     │
        │  时间   3 天前                              │
        │  清楚   较清楚                              │
        │  推算   精确度: 一位            ⚠            │
        └─────────────────────────────────────────────┘
                    │
                    ▼  自动进笔记本（不要让玩家手抄）
```

**三种语气**（契约 §M4 / 决定 B1）：

| 心情 | 表现 |
|---|---|
| 愿意说 | 正常气泡 |
| 勉强 | 气泡短、带"……" |
| 烦了 | "啊这个我刚说过吧" + **这次不回答** + 好感 ↓ |

**问多了会烦** —— UI 要**提前预警**（这个人的"耐心"用一次性的视觉提示：气泡边框变淡），而不是问完才扣。

### 4.5 笔记本 ★ 最独特的一屏

它不是日志（按时间排），是**情报库**（按可用性排）。

```
┌─ 笔记本 ──────────────────── [全部][我亲眼][听说][待确认] ──┐
│                                                              │
│ 苹果 · 吵吵小店                                   2 天前     │
│   ¥5.0    亲眼(B) · 清晰                        ← 实心      │
│   □ 我想再确认一下                               ← 可勾选    │
│                                                              │
│ 简餐 · 食品加工厂                                 26 天前    │
│   不到 5 块   听 王阿姨 说(C) · 一位                        │
│   ~ 她也是听来的                                 ← ★传了几手 │
│                                                              │
│ 梨 · 街角水果铺                                   1 天前     │
│   ¥3.5    亲眼(B) · 清晰                                    │
│                                                              │
└──────────────────────────────────────────────────────────────┘
```

**三条纪律**：

1. **永不自动刷新**（P3）。世界变了，笔记本不会跟着变。想更新 → 你要**去看**或**去问**。
2. **旧的褪色**（P2）。褪色不是装饰，是"这条该去确认了"的可视信号。
3. **标注传了几手**。`~ 她也是听来的` —— 这一行是**精度衰减的唯一可视化**，也是决定 #18 在玩家面前唯一出现的地方。

**这屏做对了，游戏就成立了。**

### 4.6 账本（A 类 · 精确 · 唯一的客观入口）

```
┌─ 账本 ──────────────────────────────────────────────────────┐
│ 今天                                                         │
│   14:02  王阿姨    苹果×2      ¥10.0        （第 11 次来）    │
│   13:40  某居民    简餐×1      ¥ 8.0        （第  1 次来）    │
│                                                              │
│ 常客                                   第几次   上次来       │
│   王阿姨                                 11     3 天前       │
│   李大爷                                  8     1 天前       │
│   张大妈                                  6    13 天前  ⚠    │ ← 她快不来了
│                                                              │
│ 讣告                                                         │
│   （无）                                                     │
└──────────────────────────────────────────────────────────────┘
```

**这一屏是"声誉"唯一的客观入口。** 你问不到声誉分（F），但你能看见"张大妈上次来是 13 天前"。

**必须能按「多久没来」排序** —— 那才是玩家真正想找的东西。

### 4.7 快进 + 结束摘要

决定 #13/#14：**快进 = 跳到，不是快放**；**有代价**（你的需求也在掉，世界在变而你没看见）。
checklist #5：**面板打开时世界继续走**（世界不等你）。

```
[⏸][1x][10x][100x]      ☑ 有人进店就停
                        ☑ 有人跟我说话就停
                        ☐ 到下一个整点


你跳过了 4 小时（14:20 → 18:20）
──────────────────────────────────────────
  有 3 个人来过店里            ← A（账本的数目, 精确）
  你没有看到他们。              ← ★ 不是"你错过了信息", 是"你不在场"
  简餐卖光了一次
  你在店里饿了 1 小时           ← 你自己的代价（#14）
──────────────────────────────────────────
   [ 看账本 ]   [ 继续 ]
```

> ★ **摘要必须故意不全。** 它说"有 3 个人来过"，**但不说是谁** —— 想知道是谁，去看账本。
> 它要说"你没看到他们"，把**缺席**变成可感知的。这样玩家才会自己决定"下次别快进"。
> 如果摘要给全，快进就没有代价了。

## 五、什么该给玩家看 / 藏（落地纪律）

> 这是架构师要的第 ⑤ 项。上游是 [契约 §2](contracts.md)，这里把它变成**画或不画**的规则。

### 5.1 每个 UI 元素都要能写出一个来源代号

```
画之前问三句:
  ① 这个字段是 A/B/C/D/E 里的哪一个？
  ② 是 【别人的记忆/钱/意图】 吗？         → F, 不画
  ③ 我答不出代号吗？                       → 不画
```

### 5.2 画 / 藏速查表

| 东西 | 画？ | 代号 | 画成什么样 |
|---|---|---|---|
| 我的钱 / 我的需求 | ✓ | A | 精确，唯一精确的地方 |
| 我的交易记录 | ✓ | A | 账本，可回溯 |
| 建筑骨架（路/门/名字） | ✓ | 常识 | 一直有 |
| 别家卖什么/多少钱 | ✓ | B/C/D | **带来源和时间；没去过就是「？」** |
| 谁站在柜台上 | ✓ | B | 只有我看见过的 |
| 我认识的人的**名字** | ✓ | A（账本见过） | 名字 + 脸 |
| 我不认识的人的**脸** | ✓ | B | **"某居民"，没有名字** |
| 别人此刻在干什么 | ✓ | B | 只在我视野内的此刻；离开就只剩"我记得" |
| 别人对我说过的话 | ✓ | C/D | 带来源，标注"他也是听说" |
| 我雇的人的位置 | ✓ | E | 标注是雇员告诉我的（有损二手） |
| 别人的钱 | ✗ | **F** | — |
| 别人的需求 / 意图 / 打算 | ✗ | **F** | — |
| 别人的原始记忆行 | ✗ | **F** | 只能问，拿到的是渲染后的一句话 |
| 别人对我的好感数值 | ✗ | **F** | 从"愿不愿意答"感觉 |
| 对手的账 / 利润 / 定价逻辑 | ✗ | **F** | — |
| 全城客流 / 份额 / 声誉分 / 排名 | ✗ | **F** | — |
| 别人之间说了什么 | ✗ | **F** | 除非传到我这儿（那就变成 D） |

### 5.3 三条硬规矩

```
① 「？」只表示"可得但还没得"。不可得的东西【不画】。
② 任何数字旁边写不出来源代号 → 删掉它。
③ 聚合/统计类的东西一律可疑 —— 它们通常就是 F 换了个说法。
```

## 六、一个游戏日（完整走一遍）

```
07:00  醒来。主界面。
       翻笔记本: "梨 ¥3.5 · 街角水果铺 · 1 天前"
       → 想: 要不要顺路去看看?  (但那样就见不到早上的客流)

08:00  经营面板。
       补货(算一下钱够不够发薪) / 【今天我去还是李四去】
       ★ 选"我去" → 本周露面 +1

09:00  在店里。B 类: 我看得见每个进来的人。
       王阿姨进来 —— 我认得她(账本见过 11 次) → [搭话]
       她说: "苹果啊？街上都五块"  ← C 类, 带来源, 自动进笔记本

12:00  关门出门。★ 我不在 = 我只有账本(A), 看不见此刻。
       走到街角水果铺 —— 亲眼看见梨价(B) → 笔记本那条刷新为"亲眼"
       顺路瞥见隔壁柜台站了个生面孔 ← 这是情报: 他们雇人了

15:00  回家。快进到明天。
       "你不在的 3 小时，有 5 个人来过。你没有看到他们。"

第 7 天  发薪日。账本: 现金 -12。
        "还差 ¥112" → 你知道这条路走到头了。
        → 要么今天亲自去站柜台(挣脸面 + 省钱), 要么涨别人的价(丢脸面)。
```

**每一格都是一个「时间 vs 钱 vs 脸面」的取舍。** 这就是决定 #12 说的"花钱和分配时间是同一件事的两面"。

## 七、上帝版 / 发行版：**同一套 UI**

决定 #16：两个构建，同一套 UI，**只换数据源**。

```
dev 出口  →  全量（含 memory / signals / intent / favor / cash）
play 出口 →  只含 A–E，别人的 memory/intent/favor/cash 一律不出门
```

**UI 的落地要求（这条是纪律，不是建议）**：

> 每个 UI 元素要能**在数据源为空时自动隐藏**，而不是分叉出两套界面。

于是：
- 开发时用上帝版验证机制（比如"她为什么不来" → 直接看穿她的记忆和好感）
- 发行时数据源变窄，**界面代码一行不改**

**这条也是"别把上帝版面板当玩家界面设计"的落实** —— 我们只设计**一套**，它宽的时候是上帝版，窄的时候是发行版。

## 八、首个可玩切片（只做四件事）

对齐 demo-plan 的验收四条。**别的全不做。**

| # | 验收 | UI 落到哪 |
|---|---|---|
| ① | 我**认得**他们 | 主界面：认识的人有名字有脸；不认识的是"某居民" |
| ② | 他们**记得**我 | 账本：第几次来 / 上次来几天前 / 按"多久没来"排序 |
| ③ | 他们**会传话** | 气泡 + 笔记本的 `~ 她也是听来的`（传了几手） |
| ④ | 我能**打听** | 关系页 → 三个动词 → 答话带来源+时间+档位 |

**这个切片需要的最小屏幕**：主界面 · 关系页 · 打听气泡 · 笔记本 · 账本。
**不需要**：我的店（可以硬编码一家）、快进（可以先不跳）、手机、雇人、装修、外面世界。

> ④ + ③ 是灵魂。① ② 是它们的支架。**先让 `~ 她也是听来的` 出现在屏幕上。**

### 8.1 数据缺口（UI 需要，现在还没有）

> 列在这里不是要 UI 去实现，只是**把账算清**：哪些是"设计已定、只差实现"，哪些是"设计未定"。

| UI 要的 | 现在 | 上游 |
|---|---|---|
| **账本**（谁来过 / 买了什么 / 第几次 / 上次来几天前） | ✗ 不存在 | 决定 §① 账本 —— **列表第一条** |
| **精度档**（`remember` → "4 块多"） | ✗ 不存在（已设计） | [契约 §1.2](contracts.md) · 决定 §② 精度衰减器 |
| **play 出口**（按 A–E 过滤过的字段集） | ✗ 不存在（现在只有全量） | [契约 §2.2](contracts.md) ★ **没它发行版免谈** |
| **打听**（问 → 带来源的答话） | ✗ 不存在 | demo-plan B3 · 契约 §四"问题语法未定" |
| **笔记本**（玩家侧） | ✗ 不存在 | demo-plan C1 |
| **玩家概念**（我是谁 / 我在不在场） | ✗ 不存在 | demo-plan A1/A2 |
| **露面露**（本周我站了几次柜台） | ✗ 不存在 | ★ 本文新提（§4.2），需要新数据 |
| **讣告** | ~ 有 `npc_died` 事件，但没有可查的名册 | 决定 E8（减员可感知） |

**三个最大的洞**：`账本` · `精度档` · `play 出口`。它们都**已经设计好了**，只差实现；

**两个未定的**：打听的问题语法（契约 §四已标未定）· 露面露怎么算（本文新提）。

## 九、明确不做

```

✗ 完整的快进摘要
✗ 对话树（台词由记忆长出来，不是选项树）
✗ 先做美化（风格未定；先占位）
```
