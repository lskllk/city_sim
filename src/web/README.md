## 设计从哪来

**UI = `proto/ui-prototype.html`（❄ 冻结的参考实现）**。
变量名、四角位置、`.pane`、`.plate`、按钮形态都照它，不自己发明。
一句话规则：**地图是彩色的，面板是一张安静的纸。**

**美术 = `art/out/`（全部资产）**。不画色块：
地面 `ground/*`、道路 `road/*`、建筑 `bld/*` + `_shadow` + `_lit`、
杂物 `props/*`、人物 `people/*`、物品 `items/*`。

## 两条线上契约（踩出来的）

**① 消息是信封**：`{kind, protocol_version, payload}` —— 数据在 `payload` 里。
`net.js` 拆掉它，上层直接看见 `{type, ...}`。

**② 指令是 `{name, args, req_id}`**，不是 `{type, ...args}`。

## 相机：两个坑，都在 view.js

**① `apply()` 必须先 clamp 再写 transform。**
反了会怎样：渲染用 clamp【前】的相机，而 `toWorld` / `screenOf`（名牌、气泡定位）
用 clamp【后】的 `cam` —— **两边不是同一个数**。症状就是"名牌跑偏""地图不居中时缩放会漂"。

**② 不夹相机（clamp）。**
试过两种夹法，都会和"缩放锚在鼠标上"打架：

```
夹在世界内             世界比视口小时可平移区间是负的 → 相机钉死
只在世界比视口大时夹    k=0.1 时 sx/k = 3000px → 照样夹到边界
```

而**一夹到边界，锚点必然漂** —— 用户要的是"锚点永远准"。所以不夹，
代价是能平移出世界之外，用 `F`（铺满）一键回来。
测试：小→大 · 大→最小，全程锚点漂 **0.000**。

**③ 纸片的偏移必须用【屏幕像素】，不能用世界单位。**
名牌间距原来是 0.8 世界单位 → 在 k=6 时变成 57px，"好像脱离画布"。
现在 `paper(..., dy)` 走屏幕像素，k 从 0.12 到 6 都是 5px。

**④ 平滑缩放的锚点必须在改 `k` 之前算。**

```js
const [wx, wy] = this.toWorld(z.sx, z.sy);   // ★ 先用当前的 k
this.cam.k += (z.k - this.cam.k) * 0.22;     // 再改 k
this.cam.x = wx*U - z.sx/this.cam.k;         // 把那个世界点钉回鼠标下
```

先改 k 再 toWorld，等于用"新 k + 旧相机"反推鼠标下的世界点 —— 不是原来那个点了。
测过：14 次滚轮能漂 25 世界单位。改对之后漂 **0.0000**。

## 输入模型（这里踩过两次，别改回去）

按下的那一刻就问上层："这个点你要不要接？"

```
onDown(世界点) → true   上层接了（拖房子 / 画路）→ 之后所有 move 都给它
               → false  没接 → 【默认就是平移相机】
```

原来的写法是"移动超过 4px 就转交上层" —— 结果相机一动 4px 就再也不动了
（拖动一卡一卡），而画路又永远等不到 pointerdown。
**两个 bug 同一个根因：把"拖"和"点"当成了互斥的两种模式。**
它们不是 —— 拖是默认，上层可以抢。

## 交互：拖 = 平移，点 = 操作

```
拖空白        → 平移相机（任何工具下都是）
滚轮          → 缩放，锚在鼠标上（不夹相机，所以锚点永远准）
右键          → 分场景：不在手势 → 取消选中；画路中 → 回初始；围区域中 → 退一个点
Ctrl+Z        → 撤销一步（整份地图快照，60 步）
Esc           → 同右键（不在手势里时）
1 / 2         → 选择 / 删除
```

**画路和围区域都是「点一下再点一下」**，不用按住拖：

```
画路    点起点（橡皮筋跟着鼠标）→ 点终点 → 建成
        两端各自吸附：节点 > 门 > 路中线 > 栅格
        落在路中段会【拆边】（a—b → a—n + n—b）
围区域  点节点围 → 点回第一个点闭合
        第一个点必须落在路/建筑上（区域要挂进世界）；之后可以点空地
        顶点落在路上会让开「路边 + 0.5m」，并且【不拆路】
```

## 摆放：真资产的半透明幽灵

```
建筑   幽灵按占地尺寸画在【贴边之后】的位置（不是鼠标位置）
环境   幽灵按资产自己的尺寸，锚点在脚底（立在地上）
       点一下应用；不点就跟着鼠标
```

## 编器的六条规则

路是【图】不是线。数据 = `nodes{} + edges{} + buildings{} + props[] + areas[]`。

```
① 吸附优先级  既有节点 > 建筑门 > 道路中心线 > 栅格
② 门即节点    房子贴好后自动把门接进路网：门上已有节点就【认领】，没有就新建
③ 没有边的节点不存在     pruneOrphans()（但【区域引用】的节点要保住）
④ 必须先有路才能摆房     规则强制，不是提示
⑤ 建筑自动贴边          退开的是【墙】：back = 半路宽 + 半自身进深 + 0.3
⑥ 删点 = 溶解           挑最"直"的一对融合 + 共线简化（否则看着还是两条）
```

⑤ 的"沿法线推"是修出来的：点正好落路上时，最近点 = 它自己，往哪边推都是猜的。

## 道路怎么画的（圆角 + 融合）

三层，照归档的 Godot 版（`shared/building_style.gd`）：

```
① 路段     一条路径装下同宽的所有段，stroke 用 cap:"butt" + join:"round"
           ★ 端头不能用 cap:"round" —— 大路接小路时，大路的端帽（半径=自己的
             半宽）会拱到小路外面，路口多一个"圆圆的屁股"
② 节点圆盘  半径 = 该节点上【最窄】那条路的半宽
           L 形同宽→外角还是圆的 · 大路接小路→不拱出去 · 尽头→圆头照旧
③ 路口倒角  相邻两条路之间填一段【与两条边都相切】的圆弧，每条边用【自己的半宽】
           解两元一次方程组：C·u0 = P·u0 + h0 + r 且 C·u1 = P·u1 + h1 + r
           h0 = h1 时自动退化成"半宽 + 半径"那个简单式
```

一条路径而不是一段一张图：逐段各画会在接缝上叠两层抗锯齿，出现白线。
贴图要走 `texture` + `matrix`，注意 **Pixi 会把贴图乘上 color** —— 用贴图时 color 给白，否则颜色被平方（`0x4c×0x4c = #171515`，路变近黑）。

## 懒加载 = "永远不出现"，不是"报错"

`assets.get()` 是懒加载的，而画地图是「数据没变就只画一次」—— 两者一撞，**贴图到货时已经画完了，永远补不上**。

```
漏 road   → 道路中线虚线不画
漏 props  → 摆放幽灵变成兜底方框（看着像"预览太大"）
```

两道保险：`preloadMap` 把会画到的类全加载；**贴图仓库带 version 号**掺进缓存 key，到货就重画一次。
